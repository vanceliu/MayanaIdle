# 48. 特效規範

## 48.1 定位

本文件規範**表現層特效**：什麼時候演、演多久、用什麼技術演。

**特效不得改變任何規則。** 成功率、安定值、掉率、傷害一律以各自的設計文件為準
（強化見 `06-equipment.md` § 6.9~6.10，印記見 `46-sigil.md`）——
本文件只描述「結果已經算出來之後，畫面怎麼呈現」。

特效分兩條技術路線，依**該畫面是什麼**決定，不可混用：

| 路線 | 適用 | 技術 |
|---|---|---|
| **DOM 特效** | 城鎮面板、背包、任務等 React 面板 | 純 CSS `@keyframes`，不加依賴 |
| **Pixi 特效** | 戰鬥畫面（`EffectLayer`，`40-pixijs-migration.md`） | Graphics／粒子／filter |

強化在鐵匠鋪面板裡，屬於 DOM 側；受擊、投射物、死亡在 Pixi 側。

---

## 48.2 效能預算

渲染上限見 `34-ui-guidelines.md` § 34.9（幀率 60、桌機解析度上限 1.5）。
特效設計必須守住這個預算，衍生兩條硬規則：

1. **filter 只給少數常駐對象**。每個掛了 filter 的容器都是一個額外 render pass；
   掛在每隻怪身上就是 N 個 pass，掛在 stage 上是每幀全畫面重繪，兩者都不可以
2. **一次性演出用 Graphics 或粒子，不用 filter**

DOM 側對應的規則是 `34-ui-guidelines.md` § 34.9.1（狀態沒變就不重建幾何）：
CSS 動畫一律只動 `transform`、`opacity`、`box-shadow`，
不animate 會觸發 layout 的屬性（`width`／`top`／`left`）。

---

## 48.3 共通參數

DOM 特效的時間與強度一律走 CSS 變數，不在各條 `@keyframes` 內寫死。
三個變數都定義在 **`:root`** —— 強化、印記等不同宿主共用同一組旋鈕；
掛在某個容器上時，其他宿主的 `calc()` 會因變數未定義而整條失效，`animation-delay` 直接變 0。

| 變數 | 預設 | 意義 |
|---|---|---|
| `--enh-fx-speed` | `1` | 整體時間倍率。1 ＝ 正式速度，調大＝慢動作 |
| `--enh-fx-scale` | `1` | 光暈與位移的強度倍率 |
| `--enh-fx-stagger` | `0.32s` | 白閃與後段之間的間隔（§ 48.4.3） |

**無障礙**：`prefers-reduced-motion: reduce` 時所有演出動畫一律關閉，只顯示結果。

### 48.3.1 連點必須能重播

玩家會連續按強化／使用印記。React 在重新渲染時**沿用同一個 DOM 節點**，
CSS 動畫不會因為 class 或內容變了就重跑 —— 第二次按下去等於沒有演出。

因此**每一個帶演出動畫的節點都要以本次演出的 token 當 `key`**，強制重新掛載：
覆蓋層、以及掛了動畫 class 的標籤／數值都算。
每次觸發演出時遞增 token，收尾的計時器也比對 token，只清掉自己那一次。

## 48.4 裝備強化（鐵匠鋪）

對應規則：`06-equipment.md` § 6.9（武器）／§ 6.10（防具）。
安定值內必定成功；超過安定值後有失敗率，**失敗即裝備消失**。

### 48.4.1 待命狀態

- 安定值內與超過安定值**共用同一種藍白呼吸**（`3s` 循環）
- 風險由既有的成功率數字與「失敗消失」紅字表達，**不另外用顏色區分待命動畫**

### 48.4.2 安定值內的結算

必定成功，是每天按幾十次的日常操作，只給**一下白閃**（`0.35s`）。
不放光環、不放碎裂，避免重複觀看疲乏。

### 48.4.3 超過安定值的結算

這是賭博時刻，成功與失敗都是**兩拍**，且**前一拍完全相同**：

| 拍 | 時間 | 成功 | 失敗 |
|---|---|---|---|
| 第一拍 | `0` ~ `0.35s` | 白閃 | 白閃（與成功完全相同） |
| 第二拍 | `--enh-fx-stagger` 之後 | 金色爆閃 `0.56s`、兩圈外擴光環（第二圈再延 `0.15s`）、裝備名彈跳、`+N` 上飄 | 紅閃 `0.44s`＋卡片震動 `0.5s`＋碎成六片飛散、本體淡出 `0.88s` |

**失敗同樣只有兩拍**：碎裂與紅閃同一拍起跑。分成三段會讓失敗比成功多一拍，
節奏對不上；紅閃前段的高不透明度正好蓋住碎片剛裂開的那一下。

**前 0.32 秒兩者不可有任何差異** —— 結果在白閃退掉的那一刻才揭曉，懸念由這個間隔製造。
要拉長或縮短懸念，只調 `--enh-fx-stagger`。

兩段必須**真正錯開**，不是疊在一起靠透明度分先後：
第二拍的元素基礎 `opacity: 0` 且不使用 `backwards` 填充，
延遲期間套用的是元素自己的樣式（不可見），時間到才由動畫接手。

### 48.4.4 實作對應

| 項目 | 位置 |
|---|---|
| 正式樣式 | `client/src/App.css` 的「裝備強化演出」區塊（**唯一出處**） |
| 觸發點 | `TownBlacksmith.tsx` 的強化結算（已有安定值與 `success`，不需另算）；新手裝走 `StarterNpc.tsx` |
| 共用狀態 | `useOneShotFx`（token／收尾計時器／卸載清除，見 § 48.3.1）—— 三個面板都用它，不各寫一份 |
| 預覽頁 | `client/demo/enhance-fx.html`（Vite dev server 下開 `/MayanaIdle/demo/enhance-fx.html`） |

- 預覽頁**直接 `<link>` `src/App.css`**，不自帶一份特效 CSS —— 兩邊各留一份必然走鐘。
  要調特效改 `App.css`，預覽頁重新整理即可。預覽頁不進 bundle
- 預覽頁另附速度、強度與**逐格**控制：演出只有幾百毫秒，設計階段要能停在任一格比對
- **時序全部寫在 CSS 的 `animation-delay`**，呼叫端不排計時器；
  唯一的 JS 計時器是演出結束後移除節點（`ENHANCE_FX_DURATION_MS`）
- 碎片以顯式編號 class（`.enh-shard--1` ~ `--6`）而非 `:nth-child` ——
  同一層還有閃光元素，位置會被擠掉

### 48.4.5 新手指導員的強化

新手裝的強化在**新手指導員**（`13-town.md` § 13.10），規則不同：只收金幣、
**必定成功**、沒有失敗機制。因此只演 § 48.4.2 那一段 —— 白閃 ＋ `+N` 浮字，
**不放金色爆閃、不放碎裂**。可強化的列同樣帶待命呼吸，已滿與不可強化的不帶。

### 48.4.6 失敗時的殘影卡片

強化失敗的裝備會**立刻**從清單移除（判定不為了演出延後，§ 48.1），
卡片隨之卸載，碎裂就沒有東西可演。因此失敗改由**殘影卡片**呈現：

- 移除前先拍一份快照（裝備 + 原本在清單中的索引），在原位置渲染一張純視覺卡片
- 殘影**沒有任何按鈕**，不可互動，演完由計時器收掉
- 面板關閉時一併清除，避免下次打開又看到上一次的碎裂

**不可以反過來做** —— 不可為了讓動畫演完而延後扣道具或刪裝備。

## 48.5 印記師

對應規則：`46-sigil.md`。印記分兩類，演出也照這條界線分：
**必定生效的五種**（混沌／刺針／重刻／精鍊／工藝）與**唯一有失敗率的突破印記**。

### 48.5.1 白閃是「可能失敗」的專屬信號

必定生效的印記**一律不放白閃**，只有單拍。白閃在強化已經被建立成
「這一發可能會失敗」的信號（§ 48.4），沿用同一套語意，玩家不必記第二組規則。

### 48.5.2 必定生效的五種

共用同一道掃光（`.sig-sweep`），差在顏色與後續動作：

| 印記 | 掃光色 | 後續 | 演在哪 |
|---|---|---|---|
| 精鍊（Tier +1） | 中性藍 | 標籤彈跳並亮起 | 該條詞綴 |
| 重刻（只重骰數值） | 中性藍 | 數值糊掉再定格 | 該條詞綴 |
| 刺針（換一條詞綴） | 紫 | 新標籤登場 | 該條詞綴 |
| 混沌（四條全重骰） | 紫 | 四條**逐條錯開 60ms** 翻動 | 全部詞綴 |
| 工藝（品質 +1%） | 金 | 品質數字彈跳 | **摘要區**（對象是整件裝備，§ 46.8） |

> 面板在結算後立刻顯示新值，所以演的一律是「新值登場」，
> **不做舊值退場** —— 那需要把舊值多留一份在畫面上，代價與收益不成比例。

### 48.5.3 突破印記：與強化共用同一條時間軸

**不另寫一份時間**，直接套 § 48.4.3 的元件（`.enh-flash-soft`／`.enh-flash-gold`／
`.enh-ring`／`.enh-float`／`.enh-flash-red`／`.enh-shake`），只用 `--fx-burst-color`
把爆閃、光環、浮字換成**新 Tier 的顏色**（Tier 色階見 `34-ui-guidelines.md` § 34.2）。
兩套各寫一份必然慢慢走鐘。

| 拍 | 成功 | 失敗 |
|---|---|---|
| 第一拍 | 白閃 | 白閃（完全相同） |
| 第二拍 | Tier 色爆閃＋兩圈光環＋標籤彈跳＋`T6` 浮字**往上** | 紅閃＋列震動＋標籤褪成 T1 灰＋`T1` 浮字**往下** |

- 浮字上下同一個元件（`.enh-float` 與 `.enh-float.is-down`）：
  **上飄＝變好、下沉＝變差**，語意靠方向讀，不另外配文案
- 失敗**不使用強化那套碎裂** —— § 46.7 的失敗只是詞綴掉回 T1，**裝備不會消失**
- 演出接在確認訊息（`46-sigil.md` § 46.7）之後；玩家取消時不演也不動任何東西

### 48.5.4 實作對應

| 項目 | 位置 |
|---|---|
| 正式樣式 | `client/src/App.css` 的「印記師演出」區塊（**唯一出處**） |
| 觸發點 | `SigilMaster.tsx` 的 `handleApply`，依 `SigilResult.success` 決定成功或失敗 |
| 預覽頁 | `client/demo/sigil-fx.html`（直接 `<link>` `App.css`，不自帶特效） |
