# 45. 遺產系統（Legacy Archive）

> **用途**：因版本淘汰而消失的角色，其完整狀態以唯讀形式保留供玩家憑弔
>
> 狀態：觸發來源為星盤大改版（`56-star-chart.md` § 56.8），存於 server 端 SQLite；遊戲尚未實作。

---

## 45.1 目的與觸發

觸發：星盤大改版上線時的一次性 server 資料遷移。

```
所有角色與帳號倉庫產生完整文字快照 → 寫入 legacy_archives → 清空遊玩資料
```

| 項目 | 規則 |
|---|---|
| 清空 | 角色、個人倉庫、帳號倉庫、公會、信箱、競技場、統計與排行榜、交易掛單 |
| 保留 | 帳號（登入、救援碼、設定）與 `legacy_archives` |
| 角色名稱 | 清空後可重新使用 |
| 季數 | 每次封存標一個季數；星盤大改版封存的是 Season 0，之後每次換季再封存一次，季數遞增 |

快照是**純文字**（JSON 字串），與遊玩中的資料結構完全脫鉤。
日後改動 `Character`、`EquipmentInstance` 等型別都不會弄壞既有的遺產紀錄。

---

## 45.2 快照內容

快照為角色的**完整狀態**，依 server SQLite 資料表收集：

| 區塊 | 來源 |
|---|---|
| 角色資料 | `characters.data` 整份原樣保存（基本資料、外觀、屬性、星盤、技能、任務、自動腳本等；日後新增的欄位自動涵蓋） |
| 裝備 | `equipment_instances`：裝備欄、背包、個人倉庫內的裝備實例 |
| 背包 | `character_bag` |
| 個人倉庫 | `warehouses`（個人） |
| 天賦 | `talent_slots` |
| 信箱 | `mailbox`（含未領附件） |
| 角色偏好 | `character_prefs`（統計、技能結晶、競技場槽等） |
| 公會 | 所屬公會名稱與職位 |
| 競技場 | `arena_records` |
| 版本 | 封存時的 server schema 版本與封存時間 |

另以獨立紀錄封存：

| type | 歸屬帳號 | 內容 |
|---|---|---|
| `sharedWarehouse` | 該帳號 | 帳號倉庫道具、裝備、倉庫金幣（`warehouse_gold`） |
| `guild` | 會長的帳號 | 公會名稱、建立時間、成員名單、公會倉庫道具／裝備／金幣 |

不封存：`bag_layouts`、`talent_bag_layouts` 等純介面排列。

### 資料結構

```typescript
interface LegacyArchive {
  id?: number;
  userId: number;
  type: 'character' | 'sharedWarehouse' | 'guild';
  /** 顯示用摘要，列表頁不需解析 payload 即可呈現 */
  label: string;          // 角色名稱、「帳號倉庫」或公會名稱
  className?: string;
  level?: number;
  /** 封存時的 server schema 版本 */
  dataVersion: number;
  /** 被封存的那一季（Season N） */
  season: number;
  archivedAt: number;
  /** JSON 字串，結構見 § 45.2 */
  payload: string;
}
```

> **payload 必須是字串**，不可存成物件。
> 日後型別改名或欄位刪除時，舊紀錄會變成無法解讀的殘骸。

## 45.3 遺產頁

### 進入方式

角色選擇畫面提供「遺產」入口，僅在該帳號有封存紀錄時顯示。

### 限制（硬性）

- **唯讀**：不可取出任何物品、不可複活角色、不可修改任何數值
- **無其他導覽**：頁面內只有「返回角色選擇」，不可前往城鎮、地圖或任何遊玩畫面
- **不佔角色格**：遺產角色不計入每帳號 4 個角色的上限
- 可手動刪除單筆遺產（刪除後不可復原）

### 顯示

- 列表：上方季別下拉選單（`Season N`，預設最新一季），一次只列該季的紀錄；卡片顯示名稱、類型、職業、等級、封存日期；資料版本不顯示
- 詳細：展開後顯示 § 45.2 的所有區塊
- 快照缺少的欄位（封存時該版本尚未有此欄位）顯示為 `—`，不可顯示 0 或猜測值

---

## 45.4 與排行榜的關係

排行榜在 server 端由角色資料計算（`37-statistics.md` § 37.4），遺產快照不參與。

---

## 45.5 統計欄位的相容性限制

遺產快照會保存不同時期的統計數值，因此：

- 統計欄位**只能新增，不可改變既有欄位的語意**
  （例如把 `totalGoldEarned` 從「不含商店賣出」改成「含賣出」）
- 若真的必須改語意，必須改用新欄位名稱，舊欄位保留原義
- 遺產頁對快照中不存在的欄位顯示 `—`

違反此限制會讓所有舊快照的數字變成錯誤資訊，且無法回溯修正。

---

## 45.6 備註

- 遺產永久保留，不設數量上限（純文字快照體積極小）
- 遺產不隨角色匯出檔帶走（匯出的是可遊玩角色，見 `19-account-character.md` § 19.9）
- 存於 server 端 SQLite `legacy_archives` 表，與遊玩資料分開
