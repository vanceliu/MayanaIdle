# 45. 遺產系統（Legacy Archive）

> **存儲層級**：帳號級別（跨角色保留）
> **存儲方式**：IndexedDB `legacyArchives` 表，純文字快照
> **用途**：`CURRENT_DATA_VERSION` 提高而被淘汰的角色，其完整狀態以唯讀形式保留供玩家憑弔

---

## 45.1 目的與觸發

提高 `config.ts` 的 `CURRENT_DATA_VERSION` 會淘汰所有舊版本角色（見 `19-account-character.md` § 19.9）。
直接刪除會讓玩家長期累積的成果毫無痕跡地消失，因此淘汰流程改為：

```
掃描過期角色 → 產生完整文字快照 → 寫入 legacyArchives → 刪除原始資料
```

快照是**純文字**（JSON 字串），與遊玩中的資料結構完全脫鉤。
日後改動 `Character`、`EquipmentInstance` 等型別都不會弄壞既有的遺產紀錄。

---

## 45.2 快照內容

快照為角色的**完整狀態**，不做取捨：

| 區塊 | 內容 |
|---|---|
| 基本資料 | 名稱、職業、等級、經驗、HP/MP、金幣、所在區域、建立時間 |
| 屬性 | 六大屬性的基礎值與加成值、未分配點數 |
| 裝備欄 | 各部位裝備，含詞綴、品質、強化值、雙手佔用狀態 |
| 背包 | 道具（含數量）與背包內的裝備實例 |
| 個人倉庫 | 道具與裝備實例 |
| **技能** | 已學習的所有技能與等級 |
| 任務 | 進行中與已完成的任務紀錄 |
| 統計 | § 37.1 的所有計數器 + 貢獻度 |
| 版本 | 淘汰當下的 `dataVersion` 與封存時間 |

共用倉庫為**帳號層級**，不屬於任何角色，故另外以一筆 `type: 'sharedWarehouse'` 的紀錄封存。

### 資料結構

```typescript
interface LegacyArchive {
  id?: number;
  userId: number;
  type: 'character' | 'sharedWarehouse';
  /** 顯示用摘要，列表頁不需解析 payload 即可呈現 */
  label: string;          // 角色名稱，或「共用倉庫」
  className?: string;
  level?: number;
  /** 淘汰當下的資料版本 */
  dataVersion: number;
  archivedAt: number;
  /** JSON 字串，結構見 § 45.2 */
  payload: string;
}
```

> **payload 必須是字串**，不可存成物件。存物件等於把當時的型別結構寫進 DB，
> 日後型別改名或欄位刪除時，舊紀錄會變成無法解讀的殘骸。

## 45.3 遺產頁

### 進入方式

角色選擇畫面提供「遺產」入口，僅在該帳號有封存紀錄時顯示。

### 限制（硬性）

- **唯讀**：不可取出任何物品、不可複活角色、不可修改任何數值
- **無其他導覽**：頁面內只有「返回角色選擇」，不可前往城鎮、地圖或任何遊玩畫面
- **不佔角色格**：遺產角色不計入每帳號 4 個角色的上限
- 可手動刪除單筆遺產（刪除後不可復原）

### 顯示

- 列表：依封存時間排序，顯示名稱、職業、等級、封存時間、資料版本
- 詳細：展開後顯示 § 45.2 的所有區塊
- 快照缺少的欄位（封存時該版本尚未有此欄位）顯示為 `—`，不可顯示 0 或猜測值

---

## 45.4 與排行榜的關係

被淘汰的角色其排行榜資料由**伺服端**依 `data_version` 自動失效，
客戶端不具備刪除排行榜資料的權限（`character_id` 在 snapshot 中是公開的，
若允許以 uuid 刪除，任何人都能刪除他人紀錄）。詳見 `37-statistics.md` § 37.4.8。

遺產頁顯示的統計數據一律讀本機快照，不查詢排行榜 API。

---

## 45.5 統計欄位的相容性限制

遺產快照會保存不同時期的統計數值，因此：

- 統計欄位**只能新增，不可改變既有欄位的語意**
  （例如把 `totalGoldEarned` 從「不含商店賣出」改成「含賣出」）
- 若真的必須改語意，必須改用新欄位名稱，舊欄位保留原義
- 遺產頁對快照中不存在的欄位顯示 `—`

違反此限制會讓所有舊快照的數字變成錯誤資訊，且無法回溯修正。

---

## 45.6 備註

- 遺產永久保留，不設數量上限（純文字快照體積極小）
- 遺產不隨角色匯出檔帶走（匯出的是可遊玩角色，見 `19-account-character.md` § 19.9）
- 遺產不上傳伺服端，純本機資料
