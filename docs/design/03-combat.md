# 3. 戰鬥系統

## 3.1 戰鬥定位

戰鬥流程走即時地圖 ARPG 方向。

不是傳統回合制，也不是一波一波固定關卡，更沒有階段切換。

玩家在地圖中持續移動，怪物透過 Pressure 機制在地圖上生成，玩家與怪物透過空間距離與視線判定進行即時戰鬥。戰鬥與探索發生在同一張地圖上，無需切換場景或階段。

## 3.2 探索模式

遊戲支援兩種探索模式：

### 自動探索

- 玩家 FSM 自動移動、搜尋目標、追蹤並攻擊
- 適合掛機放置
- 搭配戰鬥腳本與常駐腳本使用
- 怪物透過 Pressure 機制持續在地圖上生成，無需機率判定

### 手動探索

- 玩家點擊地圖控制角色移動方向
- 可手動點擊怪物選擇攻擊目標
- 未操作時 FSM 仍會自動反擊進入範圍的敵人
- 適合需要精確控制走位與目標選擇的場景

玩家可隨時在兩種模式間切換。

## 3.3 戰鬥模式

遊戲同時支援：

- 手動戰鬥
- 自動戰鬥

## 3.4 手動戰鬥

手動戰鬥中，玩家可以操作：

- 點擊地圖移動角色
- 點擊怪物選擇/切換攻擊目標
- 手動施放技能
- 使用補血藥水
- 決定是否撤退或返回城鎮

手動操作會覆蓋 FSM 的自動決策，操作完成後 FSM 繼續接管。

## 3.5 自動戰鬥

自動戰鬥行為分為兩套獨立腳本系統：

| 腳本 | 作用時機 | 職責 |
|---|---|---|
| 戰鬥腳本 | 玩家攻擊 tick 觸發時 | 攻擊技能施放、普通攻擊 |
| 常駐腳本 | 任何狀態（探索、戰鬥皆生效） | 喝水、buff 技能施放、治癒技能施放 |

另外，常駐腳本面板下方有獨立的「緊急撤退設定」，僅在角色附近有敵對目標時生效，負責回城判定（見 §3.13）。

戰鬥腳本詳見 §3.12，常駐腳本詳見 §3.13。

## 3.6 手動與自動的關係

戰鬥預設為自動進行（FSM 自動選目標、追蹤、攻擊、執行腳本）。

手動操作是「介入」而非「暫停」：**遊戲不會因為玩家操作而停下**，
手動只覆蓋「這一個決策」，覆蓋完就交還 FSM。因此手動介入只有兩個入口 ——
換目標、指定這一次出什麼招 —— 走位、追擊、出手時機、AoE 命中集合一律仍由 FSM 與既有流程決定。

### 3.6.1 點擊怪物切換目標

| 項目 | 規則 |
|---|---|
| 觸發 | 在地圖上點擊怪物，或點擊怪物列表（§ 24.8.3）的卡片 |
| 效果 | 指定為當前目標，等同覆寫 FSM 的 `targetMonsterId` |
| 判定順序 | **NPC → 怪物 → 地格移動**。點到怪物即結束，不觸發移動指令 |
| 持續 | **目標死亡即回自動**（FSM 重新選最近的一隻）。沒有鎖定，也沒有取消操作 |
| 超出範圍 | 照 FSM 既有邏輯追擊過去，追擊距離規則不變（`41-arpg-combat.md` § 3.1） |
| 已死／不存在的怪 | 指令作廢，維持原目標 |

指定目標**不改變**追擊距離、出手判定、AoE 圓心規則 ——
手動只回答「主目標是誰」，其餘全部沿用 `41-arpg-combat.md` § 3.4／§ 3.5。

> **目標死亡即回自動**是刻意的：怪物由 Pressure 持續生成（§ 3.10），
> 若手動目標死後維持空目標，玩家一分心角色就站著發呆，
> 與「放置型」的定位直接衝突。

### 3.6.2 手動施放技能

技能可綁進快捷欄（`35-inventory-constraints.md` § 35.7），與藥水共用 10 格。

依技能類型分成兩條路徑 —— **攻擊技能佔攻擊 tick，buff／治癒技能不佔**，
與「喝水屬於常駐腳本，不佔用攻擊 tick」（§ 3.7）同一條道理。

| 項目 | 攻擊技能 | buff／治癒技能 |
|---|---|---|
| 觸發 | 快捷欄的技能格（滑鼠兩段確認／鍵盤一按即發，§ 35.7.5） | 同左 |
| 施放時機 | **排入下一個攻擊 tick**，該 tick 覆蓋戰鬥腳本判定 | **立即施放** |
| 攻擊計時器 | **不重置**，仍佔用該次攻擊 tick（§ 3.7） | 不受影響 |
| 目標 | 單體技對當前目標；AoE 依 `aoeCenter` 決定圓心 | 對自己，不需目標 |
| 無怪物時 | 不施放，指令作廢 | **照常施放** |
| CD 中／MP 不足／武器不符 | **按下當場拒絕並發戰鬥日誌，不排隊等待** | 同左 |
| 有效期 | 只對「下一個」攻擊 tick 有效，執行後即消費；重複按只保留最後一次 | 不排隊，無有效期 |

> **buff／治癒不可排進攻擊 tick。** 攻擊 tick 只在「有目標且進入射程」時才觸發，
> 排進去等於「地圖上沒怪就補不了血」—— 而那正是玩家最需要手動補血的時候。

> 手動施放與常駐腳本（§ 3.13）的 buff／治癒**走同一條執行路徑**（同一份 MP 扣除、
> CD 寫入、特效佇列），只是觸發來源不同。兩份實作會走鐘，不可各寫一套。

> **不可做成立即施放並重置攻擊計時器。** 那等於玩家能靠手速多塞一次出手，
> 試驗場（`50-training-ground.md`）量到的 DPS 會與實戰不一致，
> 攻速數值也就失去意義。手動的價值是「換招」，不是「加速」。

> **CD 中不排隊**：排隊會讓「按下去之後不知道何時會放」變成常態。
> 不可用的技能格一律灰階並疊 CD 遮罩（§ 35.7.6），玩家看得到才按得準。

### 3.6.3 優先權

同一個攻擊 tick 上，決定出什麼招的順序：

```
手動指定的技能（若有且可用）
  ↓ 無
戰鬥腳本判定（§ 3.12）
  ↓ 無匹配規則
不動作（角色等待，不退回普通攻擊）
```

常駐腳本（§ 3.13）與村莊腳本（`49-village-script.md`）不受手動介入影響，照原頻率獨立運作。

## 3.7 攻擊速度與技能施放

### 幀驅動 Tick 架構

戰鬥系統基於 PixiJS Ticker 每幀更新，玩家與怪物各自維護攻擊冷卻計時器：

| 單位 | 攻擊間隔 | 說明 |
|---|---|---|
| 玩家 | 1200ms（可被加速影響） | 每次冷卻完成時，戰鬥腳本判定：施放攻擊技能 / 普攻 |
| 怪物 | 1200ms（固定） | 每隻怪物獨立計時，冷卻完成時攻擊玩家 |

另外，常駐腳本有自己的判定計時器（見 §3.13），獨立於上述攻擊冷卻。

注意事項：
- 每幀累加 deltaTime，當累計時間 >= 攻擊間隔時觸發一次攻擊 tick
- 加速只縮短玩家攻擊間隔，依攻速百分比換算：`間隔 = 1200 / (1 + 攻速% / 100)`
  - 綠色藥水 / 強化綠色藥水 / 加速術（+33%）→ 902ms
  - 強化加速術（+40%）→ 857ms
  - 減速 debuff（-30%）與攻速 buff 的百分比相加後再換算（見 `24-buff-debuff.md` § 24.4.5）
- 技能冷卻獨立計時，不受攻速影響
- 喝水屬於常駐腳本，不佔用攻擊 tick
- 攻擊前需通過距離檢查與視線檢查（Bresenham 射線）。射程數值見 `41-arpg-combat.md` § 3.1

### 基礎攻擊速度

- 角色攻擊間隔：1200ms（加速後降至 900ms）
- 怪物攻擊間隔：1200ms（固定不變）
- 綠色藥水/加速術：降低玩家攻擊間隔（×0.75）

### 技能施放規則

- 技能施放取代該 tick 的普通攻擊（不是額外動作）
- 施法時間：0.5 秒（視覺動畫）
- 每個技能有獨立冷卻時間（如風刃 3 秒）
- 冷卻中的技能無法施放，該 tick 自動執行普通攻擊
- 自動戰鬥邏輯：由腳本引擎按規則順序決定
- AOE 技能支援兩種模式：自身為中心、目標為中心

## 3.8 掉落與經驗結算

每隻怪物死亡時立刻結算，不等整場戰鬥結束：

- 該怪物的經驗值立刻加入角色（可能觸發升級）
- 該怪物的掉落立刻判定並加入背包
- 怪物死亡後 FSM 自動選擇下一個目標繼續戰鬥

### 設計理由

- 地圖上持續有怪物存在，沒有「整場結束」的概念
- 打死一隻立即有回饋，持續戰鬥體驗流暢
- 若中途死亡或逃跑，已擊殺的怪物經驗和掉落不會消失

## 3.9 怪物生成機制

MayanaIdle 的重要戰鬥特色：

怪物透過 Pressure 機制持續在地圖上生成，玩家停留越久，地圖上同時存在的怪物越多。

這代表：

- 停留時間越長，地圖上怪物密度越高
- 玩家越強，能承受越多怪物同時攻擊
- 怪物數量增加會提升收益，但也增加死亡風險
- 怪物在地圖上持續生成，不分「批次」或「回合」
- 地圖上同時存在的怪物上限為 10 隻

## 3.10 Pressure 機制

Pressure 為隱藏數值，代表地圖停留時間帶來的怪物壓力。

Pressure 影響怪物生成頻率與地圖上同時存在的怪物數量上限（最多 10 隻）。

怪物在地圖上以空間方式生成（在玩家視野範圍外的合法地格），生成後擁有獨立的 FSM（漫遊/追蹤/攻擊），會自主移動並在發現玩家後追蹤攻擊。

具體公式與生成規則見 `26-spawn-pressure.md`。

## 3.11 戰鬥流程

```text
玩家進入地圖
↓
怪物透過 Pressure 機制在地圖上生成
↓
玩家 FSM 偵測到範圍內的怪物（或怪物偵測到玩家）
↓
距離不足 → 追蹤目標（A* 尋路 / 貪心步進）
↓
進入攻擊範圍（射程定義見 `41-arpg-combat.md` § 3.1）且視線通過
↓
開始攻擊（每 1200ms 一次攻擊 tick，執行戰鬥腳本）
↓
怪物死亡 → 立刻結算經驗/掉落 → FSM 選擇下一目標
↓
新怪物持續透過 Pressure 生成（最多同時 10 隻）
↓
循環持續，直到玩家撤退、死亡、或離開地圖
```

## 3.12 戰鬥腳本

戰鬥腳本在玩家每次攻擊 tick 觸發時執行（即攻擊冷卻完成、目標在範圍內且視線通過時）。

### 規則結構

```
腳本 = 一組有序規則（由上往下判定）
規則 = 條件（可多個，AND）+ 動作
```

每次玩家攻擊 tick（1200ms，受加速影響）：從第一條規則開始，找到第一個條件成立且可執行的規則，執行其動作。若無規則匹配，角色該 tick 不動作（等待）。

一條規則可以掛多個條件，**全部成立**才觸發（AND）；條件數為 0 等同「永遠」。

### 可用條件

| 條件 | 參數 | 說明 |
|---|---|---|
| 永遠 | — | 無條件觸發 |
| 攻擊範圍內怪物數 ≥ | N | 以**這條規則自己的射程**為半徑：技能用技能射程，普通攻擊用武器射程 |
| 自身周圍怪物數 ≥ | N 隻 / R 碼 | 以角色為圓心、R 碼內的活怪數，用來判斷是否被包圍 |
| 本招命中數 ≥ | N | 依這條規則要放的技能實算會打到幾隻，見下方說明 |
| 目標 HP 低於 | X% | 當前目標 HP 百分比 |
| 目標 HP 高於 | X% | 當前目標 HP 百分比 |
| MP 高於 | X% | 角色 MP 百分比 |
| MP 低於 | X% | 角色 MP 百分比 |
| 技能就緒 | 技能名 | 指定攻擊技能 CD 完成且 MP 足夠 |

**本招命中數**：用與實際出手完全相同的目標選取邏輯（`41-arpg-combat.md` § 3.4／§ 3.5：
`aoeCenter` / `aoeRadius` / `maxTargets`）算出命中集合大小。同一條「命中數 ≥ 3」掛在
火球（半徑 3、上限 3）與流星雨（半徑 8、上限 8）上，判定的圈本來就不同，玩家不必自己記半徑。
單體技與普通攻擊的命中數恆為 1。

此條件**不做射程判定**：角色還在往怪群移動的路上時條件仍成立，否則永遠等不到走到定位，
連帶讓追擊距離塌回武器射程。射程由出手當下的目標判定負責。

**當前目標**＝戰鬥 FSM 選定的目標；未選定時為距離最近的一隻。

### 可用動作

| 動作 | 參數 | 說明 |
|---|---|---|
| 施放攻擊技能 | 技能名 | 對當前目標施放攻擊型技能 |
| 普通攻擊 | — | 物理攻擊當前目標 |
| 不動作 | — | 該 tick 跳過，角色等待 |

### 預設腳本範例

```
#1 如果 技能就緒（風刃）→ 施放風刃
#2 永遠 → 普通攻擊
```

### 多條件範例

```
#1 如果 本招命中數 ≥ 3 且 MP 高於 40% → 施放火球
#2 如果 自身周圍怪物數 ≥ 4（半徑 3 碼）→ 施放天雷
#3 如果 目標 HP 低於 30% → 施放風刃
#4 永遠 → 普通攻擊
```

### 設計要點

- 規則可新增、刪除、排序、啟用/停用；條件可在同一條規則內增刪
- 戰鬥腳本只處理攻擊行為，不包含喝水、回城、buff
- 技能施放取代該 tick 的普通攻擊（不是額外動作）
- 動作是技能時，CD／MP／武器需求由動作本身檢查，**不需要**再多掛一條「技能就緒」
- 若所有規則都未匹配（包含全部停用），角色不會自動攻擊
- 玩家可使用「不動作」明確讓角色在特定條件下等待

## 3.13 常駐腳本

常駐腳本在任何狀態下持續運作（探索、戰鬥皆生效）。

### 判定頻率

每 300ms 判定一次，從第一條規則開始，找到第一個條件成立且可執行的規則，執行其動作。

### 規則結構

與戰鬥腳本相同：有序規則列表，條件（可多個，AND）+ 動作。

### 可用條件

| 條件 | 參數 | 說明 |
|---|---|---|
| 永遠 | — | 無條件觸發 |
| HP 低於 | X% | 自身 HP 百分比 |
| HP 高於 | X% | 自身 HP 百分比 |
| MP 低於 | X% | 自身 MP 百分比 |
| MP 高於 | X% | 自身 MP 百分比 |
| Buff 未激活 | buff 名 | 指定 buff 效果不存在時 |
| 技能就緒 | 技能名 | 指定 buff 技能 CD 完成且 MP 足夠 |
| 狀態異常 | 狀態類型 | 角色身上有指定狀態：中毒／流血／詛咒或虛弱／減速（詛咒與虛弱共用淨化藥水，故合併為一項） |

### 可用動作

| 動作 | 參數 | 說明 |
|---|---|---|
| 使用藥水 | 藥水類型 | 紅/橙/白，受藥水冷卻限制 |
| 施放 buff 技能 | 技能名 | 施放輔助型技能（如魔法盔甲、祝福武器） |
| 施放治癒技能 | 技能名 | 施放回復型技能（如治癒、中治癒） |
| 使用解除道具 | 道具名 | 使用狀態解除道具（解毒藥水/止血繃帶/淨化藥水），見 `24-buff-debuff.md` § 24.10.1 |

> **減速用加速藥水對沖**：減速沒有解除道具，條件「減速」應搭配「使用加速藥水」動作（§ 24.4.6）。

> **狀態異常條件不含暈眩**：暈眩無解除道具，且暈眩期間無法使用任何道具（§ 24.10.1），寫成規則不會有作用。

### 藥水冷卻

| 藥水 | 冷卻時間 |
|---|---|
| 紅色藥水 | 600ms |
| 橙色藥水 | 900ms |
| 白色藥水 | 1500ms |
| 綠色藥水 | 使用後攻速+33%，持續 180s，與加速術/強化加速術/強化綠色藥水互斥（category: speed，見 `30-items.md` § 30.4） |
| 強化綠色藥水 | 使用後攻速+33%，持續 900s，與加速術/強化加速術/綠色藥水互斥（category: speed，見 `30-items.md` § 30.4） |

300ms 判定頻率確保藥水冷卻有實際意義。

### 預設常駐腳本範例

```
#1 如果 HP 低於 30% → 使用紅色藥水
#2 如果 HP 低於 50% 且 技能就緒（治癒）→ 施放治癒
#3 如果 Buff 未激活（魔法盔甲）且 技能就緒（魔法盔甲）→ 施放魔法盔甲
```

### 設計要點

- 常駐腳本獨立於戰鬥腳本，兩套規則各自編輯（多條件 AND 兩邊都支援）
- 不分狀態常駐生效：探索中喝水回復、戰鬥中自動補血、buff 維持
- 藥水/buff 有各自冷卻，不會每 300ms 都觸發
- UI 上與戰鬥腳本分開顯示（兩個獨立 tab）

### 緊急撤退設定

緊急撤退為獨立於規則列表的固定區塊，位於常駐腳本面板最下方。

#### 設計理由

回城與一般常駐動作（喝藥、治癒、buff）性質不同：撤退僅在戰鬥中有意義，且一旦執行會改變玩家狀態（回到城鎮）。若放在規則列表中，非戰鬥狀態下會持續匹配到撤退規則但無法執行，阻塞後續規則的判定。

#### 設定項

| 欄位 | 說明 |
|---|---|
| 啟用/停用 | 開關緊急撤退功能 |
| 條件 | HP 低於 X%（玩家自訂門檻） |
| 動作 | 回城（指定城鎮）｜固定，無其他選項 |
| 回城城鎮 | 動作為回城時，指定卷軸城鎮或「任意卷軸」 |

#### 判定邏輯

- 在 persistent loop 中獨立判定，不參與規則列表的順序匹配
- 僅在角色附近存在敵對目標時生效（即處於戰鬥狀態），無敵對目標時自動跳過
- 判定頻率與常駐腳本相同（300ms）
- 撤退判定在規則列表判定之後執行（規則列表優先）

#### 動作說明

| 動作 | 效果 |
|---|---|
| 回城 | 消耗回城卷軸，傳送至指定城鎮，脫離戰鬥。詳見 §31.7 |

> **瞬移逃跑已移除**：不消耗道具的脫戰在放置型玩法下缺乏代價，且與傳送術一併廢除（見 `22-basic-magic.md`）。舊存檔若存有該設定，載入時自動導回「回城」。

#### 預設值

- 啟用：是
- 條件：HP 低於 15%
- 動作：回城（任意卷軸）

#### UI 位置

位於常駐腳本面板規則列表下方，以分隔線區隔。不可拖曳排序，不參與規則列表。

### 戰鬥後等待

戰鬥後的 HP/MP 等待回復機制獨立於腳本系統。

**觸發條件：**
- 角色處於閒置狀態（附近無怪物在攻擊範圍內）
- HP 低於觸發門檻（預設 30%）**或** MP 低於觸發門檻（預設 20%）

**解除條件：**
- HP 達到恢復門檻（預設 60%）**且** MP 達到恢復門檻（預設 60%）

**等待中行為：**
- 不生成新怪物
- 不主動追蹤/搜尋怪物
- 手動點擊移動仍有效
- 若已出現的怪物靠近並攻擊，角色會自動反擊（等待被打斷）
- 打完後若仍低於門檻，重新進入等待

**門檻設定：**
| 欄位 | 預設值 | 說明 |
|------|--------|------|
| afterCombatHpThreshold | 30% | HP 低於此值觸發等待 |
| afterCombatMpThreshold | 20% | MP 低於此值觸發等待 |
| afterCombatHpResumeThreshold | 60% | HP 恢復至此值才解除 |
| afterCombatMpResumeThreshold | 60% | MP 恢復至此值才解除 |

此機制作用於探索階段，與常駐腳本互不影響。

## 3.14 腳本 Template

戰鬥腳本與常駐腳本可以存成多組 **template**，在面板上以分頁切換。

### 內容

一個 template 是**整包**設定：

| 內容 | 說明 |
|---|---|
| 戰鬥腳本 | § 3.12 的規則列表 |
| 常駐腳本 | § 3.13 的規則列表 |
| 村莊腳本 | `49-village-script.md` 的規則列表 |
| 緊急撤退 | § 3.13 的回城門檻與指定卷軸 |

切換情境（清怪／打王／練功）時一次到位，不必分三處各切一遍。

### 規則

- **每個角色各自獨立**：template 存在該角色的設定裡，不跨角色共用 ——
  規則裡的技能綁職業，跨職業套用會出現一堆指向沒學會技能的無效規則
- **內建一份「預設」template，不可刪除**（可編輯、可更名）。
  因此清單永遠至少有一個，不會出現「一個 template 都沒有」的狀態
- **編輯即生效即存檔**：改動直接寫進使用中的那一個 template，沒有「儲存／放棄」兩段式狀態。
  想保留舊版就先複製一份
- **新增的 template 內容為預設腳本**，不是空白 ——
  空腳本代表角色完全不出手（見 § 3.12「若所有規則都未匹配，角色不會自動攻擊」）
- 切換立即生效：下一個攻擊 tick 就換招，常駐腳本的判定計時器同步重掛
- 使用中的 template 必須在 UI 上看得出來（分頁選中狀態）
- 下排分頁為常駐腳本／戰鬥腳本／村莊腳本三個

### 不做的事

- 不做「遇到 Boss 自動切換 template」之類的自動切換 —— 玩家自己切
- 不做跨角色／跨帳號的 template 匯入匯出

## 3.15 不採用的戰鬥設計

AI 生成時應避免：

- 不要做成固定下一關
- 不要做成每關小怪、小怪、Boss、下一關
- 不要加入戰鬥速度 1x、2x、4x
- 目前不設計戰鬥加速功能
- 不要把戰鬥設計成純回合制
- 不要做成階段切換（探索階段 → 戰鬥階段）
- 不要使用機率遇敵（每秒 X% 遇敵）
- 不要把怪物分批次（一次遇敵打完一批）
