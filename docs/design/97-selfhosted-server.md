# 97. 自架私服線上模式

> 狀態：**定案，實作暫緩**。單機既有功能全部完成後才開工。本文件是線上模式的唯一規格；`98-online-architecture.md` 保留備查，不採用。

---

## 97.1 定位

遊戲只有一種執行形態：**Node server + 瀏覽器 client**，但世界分成單機與開放兩種，**一經建立即固定**。

| 形態 | bind 位址 | 誰能連 | 帳號 |
|---|---|---|---|
| 單機 | `127.0.0.1` | 只有本機 | host 帳號自動登入，**不設密碼**（§ 97.5） |
| 開放 | `0.0.0.0` | 任何持有 IP 的人 | 每個人各自註冊 |

**形態不可轉換（硬性）**：首次啟動依 `bind` 判定並寫入資料庫（`server_meta`），
之後 `bind` 改成另一種形態一律**拒絕啟動**，不是照常跑。

單機世界是在「只有自己會連進來」的前提下養出來的 —— 沒有帳號密碼、host 自動登入；
若允許改 `bind` 就對外，等於把那個世界連同無密碼的帳號一起曝出去。
要開另一種形態的世界，用另一個資料目錄（`--data-dir`）。

世界綁 server，角色綁世界：角色只存在於建立它的 server，不能帶到別的 server。

**單機世界不畫多人 UI**：聊天分頁、社群視窗（§ 97.7.5）、本地圖在線人數、交易、公會 NPC 在單機一律不出現。
形態由 server 在握手（`hello_ok`）時帶給 client —— 單機同樣是連著一個 server，
「有沒有連線」判斷不出來。

任何人取得 server 程式即可開設一個獨立世界。帳號、角色、統計、排行、交易皆限該 server 內，不跨服。

---

## 97.2 部署形態

```
單一 Node process
  ├─ HTTP  靜態檔（前端 bundle）＋ /admin
  ├─ WebSocket  遊戲通訊
  ├─ 遊戲迴圈  server authoritative
  └─ SQLite（WAL）  持久化
```

### 硬性要求

| 要求 | 規則 |
|---|---|
| 前端由 server 自己 serve | 私服無 TLS 憑證，前端掛 `https://` 時瀏覽器會擋掉 `ws://`；必須同源。正式版只連同源 server；`?server=` 指定連線位址僅開發版生效 |
| 單一可執行單元 | 不依賴外部 Redis / PostgreSQL |
| 版本協商 | 握手時比兩個版本，**都必須完全相同**，任一不符即拒連並顯示需求版本：**協定版本**（`net/protocol.ts` 的 `PROTOCOL_VERSION`）擋訊息格式不相容，**發布版本**（`client/package.json` 的 `version`）擋格式相同但行為不同的 client。協定先判。發布版本這道不可省 —— 同格式、不同版本的 client 同時在線會產生難以追查的行為差異 |
| client 無遊戲邏輯 | client 只做渲染、輸入與插值；所有判定在 server |
| tick 錯誤隔離 | tick 中單一玩家的步驟出錯：該玩家本 tick 其餘步驟跳過、記 error log、踢除（原因「角色狀態異常，已中斷連線」，踢除照常 flush），之後不再進 tick。單一實例出錯：該實例本 tick 其餘步驟跳過、記 error log；實例只有一名在場玩家時視同該玩家出錯。其他玩家與實例照常 |
| 遠端 action 允許清單 | client 只能呼叫 `net/protocol.ts` 的 `ACTION_ALLOWLIST` 列出的 action，其餘回 `action_denied`。client 專用（介面狀態）或 server 內部用（效果增減、存檔、換區、任務板產生、舊腳本規則）的 action，以及 client 介面沒有呼叫點的 action，不得列入；試驗場木樁（`mapMonster`）不經 server（本節「試驗場本機沙盒」）；介面操作提示（`pushSystemLog`）只在 client 本機顯示。任務板只在不屬於目前城鎮時重新產生（`ensureQuestBoardForTown`）；同城重刷只能走扣貢獻的 `rerollQuestBoard`（`36-quest-system.md` § 36.6.3） |
| client 端呼叫遠端 action | 參數必須可 JSON 序列化：介面事件不可直接以 store action 當處理函式（事件物件會成為參數、序列化失敗、請求送不出）。寫入持久層或連動其他 store 的後續處理寫在 store action 內、由 server 執行，介面元件不自行串接（client 沒有持久層）。背包位置（`setBagSlotMap`、天賦分頁 `setTalentBagOrder`）格式不合（非物件、值非非負整數）整筆不寫。連線未開啟時呼叫立即以「尚未連線，操作未送出」失敗、不送出；等待回應期間斷線以「連線中斷，操作結果未知」失敗。失敗時寫一行本機系統訊息（server 回傳的錯誤字串），錯誤照常交給呼叫端。整份覆寫的值（緊急撤退、天賦參數、背包與天賦分頁位置、交易內容）在送出後、回覆前的下一次修改以本機最後送出的值為基準，背包與天賦分頁的版面同樣以該值顯示。送 server 的數字輸入格打字只改本機草稿，離開輸入格或按 Enter 才送出，與目前值相同或非數字不送 |
| 試驗場本機沙盒 | 角色在試驗場（`50-training-ground.md`）時由 client 本機模擬：移動、木樁、戰鬥、天賦判定、量測、HP／MP／buff／冷卻、回復滿血滿魔只在本機（`restoreInTrainingGround` 不在允許清單）。改到角色本身狀態的操作照常送 server：換裝、天賦、技能、屬性點、道具消耗、離開。本機的道具消耗以 `consumeTrainingItems` 扣 server 庫存（只在試驗場內；任一行數量非正整數或庫存不足整筆不扣），效果套在沙盒。沙盒期間 client 不套用 server 推送的 `mapMonster`、戰鬥 delta、演出、`mapControl` 的位置／路徑／移動狀態，以及 `game` 的 `character.hp`／`character.mp`、`activeEffects`、`skills`、藥水冷卻；本機存檔一律丟棄；server 不 tick 該玩家。離開試驗場（含登出）時結束沙盒，server 整份重送狀態 |
| action 後套用搜尋模式 | 每個 action 處理完依 `searchMode` 與 `phase` 套用自動移動，只在 `autoMove` 需切換時呼叫 `setAutoMove`，不覆蓋 action 已排好的路徑（`38-map-control.md` § 38.5）；所在地圖為城鎮時一律經 `setAutoMove` 關閉自動移動（`13-town.md` § 13.2.1） |
| action 擁有權 | 以 id 指定對象的 action（裝備、丟棄、天賦格、信件），對象必須屬於自己，否則不處理。傳入完整物件的 action 只取其 id，從自己的資料取實例，其餘欄位不採用 |
| 價格與內容由 server 決定 | 雜貨店購買只收道具 id 與數量，單價依所在城鎮貨架（`13-town.md` § 13.4）；非貨架品、數量非正整數、金幣或背包格數不足整筆不成交。裝備回收價只依 server 模板快取，新手裝與無回收價者不賣。接冒險者任務只取 id，任務內容取自自己的任務板 |
| 參數驗證 | 數量參數一律正的安全整數（丟棄確認例外：0 或負數丟 1 個，非整數不處理；多項丟棄見 `35-inventory-constraints.md` § 35.5.3）；裝備欄位限 `SLOT_ORDER`；屬性鍵限六屬性；印記類型限已定義的種類、詞綴編號為 null 或範圍內整數；旅館 mode 限 full／hp／mp，且只在地區類型為城鎮時生效。不合格不處理 |
| 天賦與撤退設定驗證 | 天賦參數依該規則的參數定義逐欄位驗證（數字在範圍內、選項在清單內、道具存在、開關為布林），未定義欄位（含 `type`）丟棄，任一欄不合格整筆不寫；格位編號為 null 或非負整數；安裝類型限三種、天賦配置須存在、數量上限見 `51-auto-talent.md` § 51.3.4。緊急撤退：HP 門檻 1~100、動作固定回城、城鎮為空或已定義的卷軸城鎮（`03-combat.md` § 3.13） |
| HTTP 安全標頭 | 每個回應都帶 `X-Frame-Options: DENY`、`Content-Security-Policy: frame-ancestors 'none'`、`Referrer-Policy: no-referrer`、`X-Content-Type-Options: nosniff` |
| 機密檔案權限 | `server.properties`、SQLite（含 WAL／SHM）、備份檔一律 0600。檔案系統不支援 Unix 權限（FAT／exFAT／NTFS 等）時只記一次警告、照常啟動，存取限制改由掛載選項負責 |
| 訊息依序處理 | 同一連線的訊息依收到順序逐一處理，前一則處理完才處理下一則 |
| 錯誤訊息不終止 server | 不是合法 JSON 回 `bad_json`；JSON 合法但不是含字串 `t` 的物件回 `bad_message`；兩者皆保留連線。HTTP request URL 無法解析回 400。非預期錯誤回 client 固定字串「伺服器內部錯誤」，細節只寫 log。未處理的 Promise rejection 只記 error log，行程不結束（server 執行檔與桌面版皆同） |
| 連線心跳 | server 每 30 秒對每條連線送 WebSocket ping；上一輪的 ping 到下一輪仍沒收到 pong 即中斷連線，照一般斷線處理。收到 pong 時以 `latency` 訊息把往返毫秒數推給該連線（顯示見 `47-mobile.md` § 47.6）。間隔不可設定 |

### 發布形態

兩種產物，同一份程式碼：

| 產物 | 內容 | 給誰 |
|---|---|---|
| **桌面版**（Electron） | 啟動器 ＋ server ＋ 前端，一個 app | 一般玩家 |
| **server 執行檔**（Node SEA） | server ＋ 前端，無視窗 | 想長時間開站的人 |

| 項目 | 規則 |
|---|---|
| 設定檔 | `server.properties`，見下節；首次啟動自動產生 |
| 手機 | 只作為 client 連線至 server，無本機單機 |
| 平台 | server 執行檔：Linux x64、Linux arm64（64 位元樹莓派）、macOS arm64、Windows x64 各一份，可在單一機器交叉打包。桌面版：三平台都出，但各平台需在該平台打包 |
| 原始碼執行 | `node server/dist/server.js`（前端讀 `client/dist`） |

#### 桌面啟動器

開啟後先出啟動器，三個入口：

| 入口 | 行為 |
|---|---|
| 單機開始 | 在 app 行程內起 server（`bind` 127.0.0.1），載入遊戲。**一鍵就走**，沒有要設定的東西 |
| 開放（開站） | 先列出**已建立的 server**（各自的名稱、埠、註冊模式），選一個啟動；或建立新的 |
| 連線到別人的 server | **不起本機 server**；輸入位址或選最近連線，直接載入對方的遊戲頁 |

| 項目 | 規則 |
|---|---|
| 資料目錄 | 單機一個（`<userData>/worlds/solo`）；開放世界**可以有多個**，一個世界一個目錄（`<userData>/worlds/open/<代號>`）。分開放才不會讓形態鎖定（§ 97.1）從側門被繞過 |
| 建立新 server | **不套預設值直接建**：先在頁面上把 `server.properties` 的鍵填好，按下建立才寫檔並啟動。埠與既有世界重複即擋下 |
| 編輯設定 | 既有世界在頁面上改同一份 `server.properties`（欄位與預設值來自 server 的設定規格，不另寫一份）。檔案裡原有的鍵、包含表單沒列的，一律保留 |
| `bind` | 不在表單上：開放世界固定 `0.0.0.0`、單機固定回送位址。形態一經建立即固定，讓人填等於能建出永遠壞掉的世界 |
| 本機載入位址 | 一律 `127.0.0.1` —— `0.0.0.0` 是監聽位址、連不上；要給別人的區網位址顯示在視窗標題與記錄檔 |
| 位址輸入 | 接受 `host`、`host:port`、整條網址；沒寫埠用 25580。連線前先打 `/api/version` 確認對方是本遊戲的 server |
| 最近連線 | 存本機（`<userData>/servers.json`），可命名、可移除，上限 20 台。**沒有中央登錄服務** |
| server 的生命週期 | 與遊戲畫面同進退：**回到啟動器或關掉 app，server 一定跟著關**。不另外做「是否執行中」的顯示 —— 啟動器頁面出現時它必然已經關了 |
| 回到啟動器 | 選單「遊戲 → 回到啟動器（會關閉 server）」（⌘L）。還有人在線時先確認，關掉會把他們踢下線（資料已存） |
| 起不來時 | 埠被占用等錯誤直接顯示在啟動器上，並給「編輯設定」當場改 |
| 刪除世界 | 需二次確認，整個資料目錄移到垃圾桶（不是永久刪除） |

#### server 執行檔

| 項目 | 規則 |
|---|---|
| 產物 | 單一執行檔（Node SEA），內含前端 bundle 與靜態模板 |
| 啟動 | 雙擊後啟動 server 並依 `auto-open-browser` 開啟預設瀏覽器連 `http://127.0.0.1:<port>` |
| 資料目錄 | `--data-dir`，未指定時為 `./data` |

### 設定檔 `server.properties`

server 的所有可調項目只有這一個來源。檔案位於資料目錄，`key=value` 格式，UTF-8，`#` 開頭為註解；首次啟動以預設值產生。

| 鍵 | 預設 | 型別 | 說明 | 生效時機 |
|---|---|---|---|---|
| `server-name` | `MayanaIdle` | 字串 | 登入畫面與管理介面顯示的名稱 | 即時 |
| `bind` | `0.0.0.0` | 字串，不可為空 | 監聽位址；`0.0.0.0` 為開放形態、回送位址為單機形態（§ 97.1）。server 執行檔與原始碼執行吃這個預設；桌面啟動器建世界時一律明寫（單機 `127.0.0.1`、開放 `0.0.0.0`） | 重啟 |
| `port` | `25580` | 整數 1~65535 | 監聽埠 | 重啟 |
| `max-players` | `50` | 整數 1~100000 | 同時在線上限（§ 97.3） | 即時 |
| `registration` | `open` | 列舉 | `open`／`invite`／`closed` | 即時 |
| `invite-code` | 空 | 字串 | `registration=invite` 時的邀請碼 | 即時 |
| `admin-user` | `admin` | 字串 | 管理介面的帳號（§ 97.8）。**不是遊戲帳號** | 即時 |
| `admin-password` | 空 | 字串 | 管理介面的密碼（明文）。留空＝管理介面停用 | 即時 |
| `trust-proxy` | `false` | 布林 | 放在反向代理後方時開啟：來源 IP 改取 `X-Forwarded-For` 最右一筆，沒有該 header 時用連線對端。直接對外時必須關閉，否則來源 IP 可偽造 | 即時 |
| `auto-open-browser` | `true` | 布林 | 啟動時開啟預設瀏覽器 | 重啟 |
| `backup-dir` | `<資料目錄>/backups` | 路徑 | 備份檔存放目錄（§ 97.8） | 即時 |
| `gold-rate` | `1.0` | 小數 ≥ 0 | 全域金幣倍率，掉落與任務獎勵共用（`19-account-character.md` § 19.9 的 `GOLD_RATE_MULTIPLIER`） | 即時 |
| `drop-rate` | `1.0` | 小數 ≥ 0 | 全域道具掉落倍率（同上的 `DROP_RATE_MULTIPLIER`） | 即時 |
| `exp-rate` | `1.0` | 小數 ≥ 0 | 全域擊殺經驗倍率（同上的 `EXP_RATE_MULTIPLIER`） | 即時 |
| `pressure-rate` | `1.0` | 小數 ≥ 0 | Pressure 累積倍率（同上的 `PRESSURE_RATE_MULTIPLIER`） | 即時 |
| `spawn-rate` | `1.0` | 小數 > 0 | 怪物生成倍率，乘在一波的隻數上（同上的 `SPAWN_RATE_MULTIPLIER`），≤ 0 為非法 | 即時 |
| `monster-hp-rate` | `1.0` | 小數 > 0 | 怪物血量倍率（同上的 `MONSTER_HP_MULTIPLIER`），≤ 0 為非法；只作用於改動後新生成的怪物 | 即時 |
| `monster-attack-rate` | `1.0` | 小數 > 0 | 怪物攻擊力倍率（同上的 `MONSTER_ATTACK_MULTIPLIER`），≤ 0 為非法；只作用於改動後新生成的怪物 | 即時 |
| `boss-spawn-rate` | `1.0` | 小數 ≥ 0 | Boss 生成機率倍率（同上的 `BOSS_SPAWN_RATE_MULTIPLIER`），0 = 不生成 Boss | 即時 |

- **型別是硬性的**：整數欄不收小數與負數，小數欄不收負數，標「> 0」的連 0 都不收
  —— 0 隻怪、0 血、0 傷害會讓遊戲停擺，而金幣／掉落／經驗／Pressure／Boss 這幾項填 0 是「關掉它」的合法用法
- 桌面啟動器的設定表單依本表的型別產生輸入框，存檔前跑的是 server 啟動時的同一支驗證
- 讀取失敗或鍵值非法：印出該鍵與原因後中止啟動，不以預設值靜默帶過
- 檔案中缺少的鍵：以預設值補寫回檔案
- 未列於本表的鍵：忽略並警告
- 生效時機為「重啟」的鍵，改動後由管理介面標示需重啟，server 不自動重啟

### 命令列與 headless 執行

執行檔為一般命令列程式，行為全由 `server.properties` 決定；命令列只指定資料目錄。

| 參數 | 預設 | 說明 |
|---|---|---|
| `--data-dir <path>` | `./data`（相對於工作目錄） | 資料目錄：`server.properties`、SQLite 檔、備份目錄。不存在即建立 |

| 規則 | 內容 |
|---|---|
| headless | 無圖形環境（Linux 無 `DISPLAY` 與 `WAYLAND_DISPLAY`）時忽略 `auto-open-browser`，其餘行為與桌面相同 |
| 啟動輸出 | stdout 印出 server-name、連線位址、`/admin` 位址、資料目錄、目前 bind 形態 |
| log | 一律 stdout／stderr，不寫檔；交由 journald、Docker 等外層收集 |
| `SIGTERM`／`SIGINT` | graceful shutdown：拒新連線 → 全玩家強制 flush（§ 97.4）→ 關閉 SQLite → 結束。**訊號是立即執行**；管理介面的那顆按鈕另有 60 秒倒數（§ 97.8） |
| 服務化 | 以 systemd、Docker 等外層工具常駐，server 本身不做 daemon 化與自動重啟 |

### 狀態同步

server → client 的遊戲狀態一律走 `frame` 訊息（`net/protocol.ts`），編碼與還原共用 `net/syncCodec.ts`。

| 規則 | 內容 |
|---|---|
| 一次推送一則 | 每個 tick 對每條連線最多送一則 `frame`；操作回應的推送也是一則 |
| tick 推送 | 帶 `now`（遊戲時間）、怪物戰鬥變動、演出；有角色時每個 tick 必送，作為 client 對時與插值的心跳 |
| 操作回應推送 | 只帶 store 變動，不帶 `now`；沒有變動不送 |
| store 變動 | 各 store 頂層欄位以參照比對，只送變動的欄位；`merge`／`append` 欄位改與上次送出時的淺拷貝比對（遊戲邏輯會就地改寫角色欄位） |
| 欄位編碼 | 預設整值取代（`set`）。`game.character` 只送變動的子欄位（`merge`）；`game.combatLogs` 只送尾端新增的筆數並附總筆數（`append`）。不符合條件（子欄位被移除、陣列整份換掉）時改送整值 |
| 怪物位置 | `mapMonster.monsters` 只送 `id`、`position`、`isBoss`、`attackRange`、`dummy`，內容不變不送。`prevPosition` 由 client 以上一次收到的位置推得；tick 推送沒有怪物更新時，client 把 `prevPosition` 對齊目前位置 |
| 怪物戰鬥 | 新出現或最大血量變動的怪物送完整資料；之後只送變動的目前血量、移除的 id；目標與詠唱進度只在變動時送。session 的第一則帶 `full`，client 先清空再套用 |
| 重送完整狀態 | 登出時清掉該 session 的已送紀錄，下一則推送送完整狀態；重連是新 session，同樣從完整狀態開始 |

## 97.3 規模

| 項目 | 值 |
|---|---|
| 初期目標 | 10 ~ 50 人 |
| 架構目標 | 數百人 |
| `maxPlayers` | 設定檔可調，滿載拒連並回明確原因 |
| tick 間隔 | 300ms，不可設定（見 § 97.6） |

### 承載上限的判定

`maxPlayers` 上限以實測 tick 耗時決定，不預設數字。Server 必須輸出 tick 耗時監控（平均／p99／超時次數）。

單一 tick 無法完成全服計算時，依序採用：

1. tick slot 分攤 —— 玩家分配到固定 slot，單一 tick 只處理該 slot
2. in-process 事件排程 —— 以最小堆排「下次觸發時間」取代逐 tick 掃描，不使用 Redis
3. `worker_threads` 分片 —— 每個 worker 負責一段玩家，SQLite 寫入集中於主執行緒

### 頻寬

上行需求以 `98-online-architecture.md` § 10 的 1~2 KB/s/人 估算。開服者上行頻寬為開放形態的硬性門檻。推送格式見 § 97.2「狀態同步」。

## 97.4 資料

| 資料 | 位置 |
|---|---|
| 帳號、角色、背包、裝備實例、倉庫 | server SQLite |
| 統計、排行榜 | server SQLite，由 server 計算 |
| 靜態模板 | 隨程式碼發布，server 啟動載入記憶體（`98-online-architecture.md` § 13 同構） |
| 天賦配置、快捷鍵、UI 偏好 | server SQLite，綁角色 |
| client 端 | 僅 UI 狀態與模板快取，無遊戲資料 |

Schema 見 `18-data-schema.md` § 18.12。

### 寫入策略

```
遊戲迴圈  →  記憶體 dirty 標記（per player，`LoopState.saveDirty`）
              ↓ 每 5 秒 flush（只寫有變的表）
           SQLite（WAL，synchronous = NORMAL）
```

- flush 寫最終狀態，不寫增量事件
- **只寫有變的表**：背包與倉庫都是「全刪再逐筆寫」，內容沒變就跳過（以內容簽章比對）
- 強制 flush 時機：玩家登出、server graceful shutdown、交易換手、角色死亡、強化判定、玩家斷線、同帳號另一處進場（§ 97.5）
- crash 最壞損失 5 秒進度
- `synchronous = NORMAL`：提交不再每次 fsync，資料庫不會損壞，斷電時最多掉最後幾筆已提交交易
- **寫入關卡（硬性）**：全 server 共用一條連線，所有寫入（repository、帳號、公會、管理介面）一律經 `db/writeGate.ts`。
  交易的 BEGIN 可跨 await，只併入**同一呼叫鏈**的巢狀呼叫（`AsyncLocalStorage`）；其他呼叫鏈的交易與寫入排在其後，
  沒有交易開著時立即寫入。不得在關卡外直接下寫入語句或 `BEGIN`

### Schema 遷移

- 資料結構變更以 server 啟動時的遷移腳本處理，版本號存於 SQLite
- 不做「提高版本號淘汰所有角色」；`CURRENT_DATA_VERSION` 機制廢止
- 遷移必須冪等，失敗即中止啟動，不得半套
- schema v4：既有 T7 裝備實例補抽獨有詞綴（`07-affix-tier7.md` § 7T.2），已有的不重抽

### 排行榜

- server 全量計算後推送，範圍為本服
- 全服共用快照，**1 分鐘**內最多重算一次；期間的請求直接回快照（client 另有自己的快取，`13-town.md` § 13.3）
- 欄位與顯示規則見 `37-statistics.md` § 37.4
- 單機形態的排行榜即一人榜，不做特例；全球榜不存在

## 97.5 帳號與身分

各 server 各自註冊。

| 項目 | 規則 |
|---|---|
| 帳號 | username + password，server 端以 argon2id 儲存 |
| 連線憑證 | server 簽發 session token，有效 30 天；資料庫只存 token 的 SHA-256，簽發時順手清掉過期列 |
| 同連線換帳號 | 換到別的帳號前先卸下目前角色（照常 flush），角色資料不跨帳號 |
| 角色歸屬 | 綁 server 端帳號，不綁瀏覽器 |
| 進入流程 | 登入 → 角色選擇（`19-account-character.md` § 19.3）→ 進入遊戲 |
| 同時在場 | 一個帳號同時只能有**一隻角色在遊戲中**，同一隻角色重開也算。停在角色選擇畫面的連線不受限 |
| 重複進場 | 後進場的贏：進入遊戲（選角或建角）前，同帳號其他在場的連線一律踢除（同 § 97.8 踢除連線：先強制 flush 再斷線），flush 完成後新連線才讀角色。同帳號的進場依序執行 |
| 被踢的一方 | 自動重連後停在角色選擇畫面，不自動選回角色；畫面顯示「此帳號已在其他地方進入遊戲」，選角或建角後清除 |
| 斷線重連 | 自動重連登入後直接進入斷線前遊戲中的角色（server 端照一般選角處理，含重複進場規則）。斷線前停在角色選擇、被踢除、主動回角色清單或登出時不自動進入；選角失敗停在角色選擇畫面。記錄只存在 client 記憶體，重新整理頁面不適用 |
| 角色格數 | 沿用 `19-account-character.md` § 19.2 |
| 角色識別 | `uuid` 由 server 建立時產生，公開；無 client 端密鑰 |
| 改密碼 | 設定視窗輸入新密碼，並驗證目前的密碼**或**救援碼；完成後撤銷同帳號其他 session 並踢除其他連線，只保留目前這條 |

### 救援碼

玩家自助重設密碼的唯一管道。權限高低：救援碼 > 密碼 > session，**玩家只能用救援碼換救援碼**（管理員發碼見 § 97.8）。

| 項目 | 規則 |
|---|---|
| 格式 | `<帳號 ID>-XXXX-XXXX-XXXX-XXXX`；隨機部分 16 字 Crockford Base32（80 bits，CSPRNG） |
| 輸入容錯 | 不分大小寫，忽略空白與 `-`；`O` 視為 `0`，`I`／`L` 視為 `1` |
| 儲存 | 只存 argon2id 雜湊；每帳號同時只有一組 |
| 發放 | 註冊成功、重設成功時各顯示一次，可直接關閉 |
| 設定視窗產生 | 帳號還沒有救援碼：驗證目前的密碼。已有救援碼：驗證**目前的救援碼**，舊碼立即失效 |
| 既有帳號 | 不補發，由玩家在設定視窗產生 |
| host 帳號 | 不發 |
| 重設 | 登入畫面「忘記密碼」輸入救援碼＋新密碼：設新密碼 → 撤銷該帳號全部 session → 踢除該帳號全部連線 → 發新救援碼並直接登入 |
| 被封鎖的帳號 | 重設失敗，同登入 |
| 救援碼遺失 | 無法自行換發（即使仍在登入中）；由管理介面發新救援碼（§ 97.8），玩家再用它自行重設 |

### 登入嘗試限制

| 項目 | 規則 |
|---|---|
| 對象 | 登入、救援碼重設、改密碼、設定視窗產生救援碼共用一組計數 |
| 計數單位 | 連線來源 IP（`trust-proxy`，§ 97.2） |
| 鎖定 | 失敗 5 次鎖 15 分鐘；鎖定期間直接拒絕，不驗證 |
| 並行 | 進行中的嘗試計入上限：失敗數 + 進行中達 5 時，新嘗試直接拒絕，不驗證 |
| 失敗 | 帳號不存在、密碼錯、救援碼錯或格式不符（含改密碼與產生救援碼時的驗證）。新密碼不合規則不算 |
| 歸零 | 成功、觸發鎖定、距上次失敗超過 15 分鐘 |
| 保存 | 記憶體，重啟即清空 |

### 註冊限制

| 項目 | 規則 |
|---|---|
| 計數單位 | 連線來源 IP（`trust-proxy`，§ 97.2） |
| 上限 | 每 IP 滾動 60 分鐘內最多建立 **2** 個帳號；超過回 `rate_limited`，不驗證 |
| 並行 | 進行中的註冊計入上限 |
| 佔用名額 | 只有帳號實際建立才佔用；帳號格式、密碼強度、帳號已存在、邀請碼錯誤等被拒的註冊不佔用 |
| 保存 | 記憶體，重啟即清空 |

### 角色名稱

角色名稱在本服唯一，規則與比對方式見 `19-account-character.md` § 19.4。

### host 帳號

| 項目 | 規則 |
|---|---|
| 建立 | **只有單機世界有**，首次啟動自動建立，username 固定為 `host` |
| 登入 | 本機連線自動登入，不顯示登入畫面 |
| 密碼 | **不設密碼**。只有本機連得進來，而且單機世界不會變成開放（§ 97.1），沒有要保護的對象。單機要設密碼的只有管理介面，即 `admin-password`（§ 97.8） |
| 開放世界 | 沒有 host 帳號，每個人各自註冊；密碼由玩家自己在遊戲的設定視窗設定；忘記時用救援碼自助重設，救援碼也遺失時由管理介面發新救援碼（§ 97.8） |

### 本模式廢止的功能

| 功能 | 取代 | 出處 |
|---|---|---|

| IndexedDB（Dexie）持久層 | server SQLite | `16-tech-frontend-architecture.md` § 32.10 |

## 97.6 決定性要求（硬性）

- 禁用 `Math.random()`，一律 seeded PRNG
- 禁止依賴 `Date.now()` 與幀率，遊戲時間一律以 tick 計數表示
- 數值運算使用整數或固定小數
- 遊戲邏輯為純函數，只在 server 執行；client 不含任何判定

tick 間隔固定 300ms，所有冷卻與間隔為其整數倍（`98-online-architecture.md` § 2 的對齊表）。

**非同步佇列一律每個 session 一份**（`stores/session.ts` 的 `LoopState`）：
掉落結算、存檔、天賦與信箱初始化都在 `await` 持久層，放在模組層就變成全服共用一條 ——
一個人的掉落會卡住另一個人的存檔。演出佇列（`selfCastFx`）同理。

### 97.7.1 地圖實例與可見性

**實例單位為隊伍**，單人視為一人隊伍。同一張地圖同時存在多個隊伍實例。

| 項目 | 規則 |
|---|---|
| 隊伍人數上限 | 5（含隊長） |
| 地圖上的人物 | 只渲染自己與隊友 |
| 非隊友 | 僅出現在該地圖的在線名單（社群視窗「在線」分頁，§ 97.7.5），無座標、不佔格、不參與戰鬥；名單只列名稱、職業、等級，動作有邀請、密語、提出交易 |
| 名單不透露隊籍 | 「已有隊伍」只在**自己邀請被回絕**後才標在那個人身上，對方離隊即取消標記。未邀請過看不出誰有隊伍 |
| 人數顯示 | 本地圖在線人數（**含自己**）標在地圖選擇器的「目前:」上；面板按鈕不標同一個數字 |
| 怪物、Pressure、掉落 | 各隊伍實例獨立 |
| `occupationManager` | 只容納自己、隊友與本實例怪物 |
| 試驗場 | 例外：一律個人實例、在線名單為空（`50-training-ground.md` § 50.2） |
| 換區載圖中 | 不放進任何實例；載圖完成後才放入新地圖的實例 |

60 張既有地圖不需放大或重畫；隊伍實例即為分流單位，不另做 channel。

#### 實例生命週期與 Pressure

實例以（隊伍，地圖）為鍵；同一隊伍的成員可在不同地圖，各自屬於不同實例。

| 事件 | 行為 |
|---|---|
| 隊伍第一位成員進入該地圖 | 建立實例，Pressure 由 0 起算 |
| 該實例的在線在場人數歸零 | 銷毀實例，Pressure 歸零 |
| 個別成員離開或離線但實例仍有人 | 實例與 Pressure 續存，該成員回來接續 |
| 成員入隊時人在野外，該地圖已有隊伍實例 | 切入該實例並於地圖入口重生；原一人實例銷毀 |
| 成員入隊時人在野外，該地圖沒有隊伍實例 | 原一人實例直接轉為隊伍實例；位置、怪物、Pressure 不變 |

累積擊殺數為隊伍全體共計。`26-spawn-pressure.md` § 26.3 的「離開地圖歸零」在本模式改以實例為單位判定；一人隊伍的行為與現行單機一致。

同節的「載入角色歸零」同樣以實例為單位：實例還有人在場時，回線的成員接續實例既有的累積擊殺數，不把它清掉。

#### 怪物上限

```
maxMonsters = min(20, 3 + Pressure + (隊伍人數 − 1) × 2)
```

單人另受 `26-spawn-pressure.md` § 26.2 的 `min(10, 3 + Pressure)` 約束，結果與現行單機相同。

| 人數 | P=0 | P=1 | P=3 | P=5 | P=7+ |
|---|---|---|---|---|---|
| 1 | 3 | 4 | 6 | 8 | 10 |
| 2 | 5 | 6 | 8 | 10 | 12 |
| 3 | 7 | 8 | 10 | 12 | 14 |
| 5 | 11 | 12 | 14 | 16 | 18 |

#### 怪物目標

目標只在判定時刻變更，判定間隔 5 秒。

| 時機 | 規則 |
|---|---|
| 初始目標 | 離怪物最近的隊伍成員 |
| 每 5 秒判定 | 候選為脫離範圍內的隊伍成員，取其中最近 5 秒傷害最高者 |
| 判定時無候選 | 取最近的隊伍成員 |
| 判定之間 | 不換目標；目標走出脫離範圍仍維持追擊至下次判定 |
| 目標死亡或離線 | 不等下次判定，立即取最近的隊伍成員 |
| 詠唱中目標死亡或離線 | 視同 `25-monster-system.md` § 25.11.1 的中止，不出手；重選目標後重新讀條 |

- 仇恨觸發：任一在場成員進入 10 格即激活；脫離以當前目標計算 15 格（`25-monster-system.md` § 25.8）
- 每隻怪物對每位成員維護最近 5 秒受傷量，只存於 server
- 攻擊型別、射程、減傷、投射物、詠唱與 debuff 規則不變；沒有任何技能改變怪物目標，挑釁怒吼維持 `23-class-magic.md` 的傷害與降攻效果

#### 掉落與經驗

| 項目 | 規則 |
|---|---|
| 參與判定 | 怪物死亡時在線且位於同一隊伍實例即算參與，不看傷害貢獻 |
| 掉落分配 | 隨機分配給一人，模式由隊長設定（§ 97.7.3）：**全隊**（所有在線成員，不限地圖）或**僅參與者** |
| 經驗分配 | 只在參與者之間平分；不同地圖的成員不共享經驗 |

死亡即離開地圖並傳送至城鎮（`38-map-control.md` § 38.8），死亡成員不計入參與。離線成員不計入任何分配。

### 97.7.2 聊天頻道

| 頻道 | 收訊範圍 |
|---|---|
| 世界 | 全服在線玩家 |
| 公會 | 同公會成員（`11-guild.md`）；無公會時拒絕「尚無公會」，輸入格停用 |
| 隊伍 | 同隊伍成員 |
| 城鎮 | 同一座城鎮內的玩家（`13-town.md` § 13.1） |
| 密語 | 指定的單一角色，收訊者與發話者兩邊都顯示 |

無陣營頻道（`15-excluded.md` § 15.7）。

| 項目 | 規則 |
|---|---|
| 視窗 | 聊天是**紀錄視窗的一個分頁**（`16-tech-frontend-architecture.md` § 32.3.1），不是獨立視窗，也不與戰鬥訊息混成同一份 log。不放面板按鈕列 |
| log | **全頻道共用一份**，照時間排；上面那排分類鈕只決定顯示與否，可多選 |
| 發言頻道 | 由輸入格左邊的選單決定，與顯示過濾互不影響 |
| 密語對象 | 以**角色名稱**指定，大小寫不分（名稱在本服唯一，見 `19-account-character.md` § 19.4）。對方不在線上、名稱查無此人、密語自己一律拒絕 |
| 顯示 | 不顯示時間戳；每行標頻道；頻道標與內文依頻道上色：世界白、隊伍藍、城鎮咖啡、公會綠（`--chat-*` token）；密語的送出與收到用不同顏色 |
| 點玩家名稱 | **一律設為密語對象**。聊天視窗裡點名字只會有一種結果；邀請組隊與提出交易在社群視窗「在線」分頁（§ 97.7.5） |
| 訊息保存 | **不保存**。只即時轉發，不寫入 SQLite —— 人一多資料量會暴增，而現階段沒有需要回溯的紀錄。要改成保存必須先定保留期限 |

#### 發話頻率與禁言

| 項目 | 規則 |
|---|---|
| 計次頻道 | **只有世界與城鎮**。隊伍、公會、密語不計次 —— 騷擾發生在公開頻道，密語連送不該把自己禁掉 |
| 禁言生效範圍 | **所有頻道**，含隊伍與密語。被禁言就是不能發話 |
| 頻率上限 | 10 秒內超過 5 則即觸發，**超出的那一則不送出** |
| 禁言長度 | 1 分鐘 |
| 累犯 | 5 分鐘內超過 3 次禁言，第 4 次起改為 30 分鐘；第 5 次以後維持 30 分鐘，不再往上疊 |
| 被擋下的回應 | 「禁言中，無法發話」，**不報剩餘秒數** |
| 狀態存放 | 只存記憶體，server 重啟即清。角色離線即清掉發話計數；**未到期的禁言（含手動）與累犯紀錄保留**，重新進場不解除 |
| 手動禁言 | 管理介面可指定時長禁言與解除（§ 97.8），手動禁言不計入累犯次數 |
| 空訊息 | 不計次 |
| 單條字數上限 | **50 字**。以碼位計：**英文字母、標點、中日文各算 1 字**，全形半形不分；表情符號的代理對也算 1 字。超過即退回「單條訊息最多 50 字」，**不截斷、不計次**；輸入框同步限制字數 |

### 97.7.3 組隊

| 項目 | 規則 |
|---|---|
| 建立 | 任一玩家邀請另一人，對方確認後成隊；建隊者為隊長 |
| 邀請入口 | 兩處：社群視窗「在線」分頁的在線名單（§ 97.7.1）；「隊伍」分頁的**角色名稱輸入格**（不同地圖的人只能這樣邀，大小寫不分）。聊天視窗不做邀請 |
| 邀請對象限制 | 對方未在任何隊伍；隊伍未滿 5 人 |
| 隊長權限 | 邀請、踢人、轉讓隊長、設定掉落分配模式 |
| 掉落分配模式 | 全隊／僅參與者，預設僅參與者；改動即時生效。隊長看到選單，隊員只顯示目前模式的文字 |
| 主動離隊、被踢 | 立即生效，該成員回到一人隊伍 |
| 斷線 | 只標記離線，隊籍保留；離線成員不佔地圖、不參與分配 |
| 離線成員回線 | 自動回到隊伍；所在地圖若仍有隊伍實例則接續，否則新建 |

| 隊長離隊 | 隊長交給在線成員中入隊最早者 |
| 解散 | 隊伍只剩 1 人時自動解散 |
| 跨地圖 | 允許，實例規則見 § 97.7.1 |
| 傳送到隊友 | 不提供 |
| 等級差 | 不做等級差的經驗或掉落懲罰 |
| 城鎮 | 城鎮無實例，隊伍狀態維持，回城不離隊 |
| 隊伍 HUD | 一列隊員：名稱、職業、HP／MP 條、所在地圖、離線標記；不顯示隊員 buff |
| 隊伍分頁 | 社群視窗的「隊伍」分頁（§ 97.7.5），只放隊伍本身（成員、掉落模式、離隊、以名稱邀請） |
| 操作結果訊息 | 只屬於當次操作：操作成功且無訊息時清除；開啟面板時由 server 清除（`party.clearMessage`），同一則訊息再發生時照常顯示 |
| 隊伍頻道 | 見 § 97.7.2 |

### 97.7.4 交易

本服玩家之間，即時寫 SQLite。

| 項目 | 規則 |
|---|---|
| 入口 | 社群視窗「在線」分頁的在線名單與「隊伍」分頁的成員列，**不放面板按鈕列** |

## 97.8 管理介面

Web UI，掛在 § 97.2 的同一個 HTTP server，路由 `/admin`。沿用既有 CSS 設計 token。

### 管理員身分

**管理員不是玩家。** 管理介面的憑證與遊戲帳號完全分離：遊戲帳號沒有 admin 旗標，
管理員也不需要有角色。管理介面管的是玩家帳號與 server 本身。

| 項目 | 規則 |
|---|---|
| 認定方式 | `server.properties` 的 `admin-user`／`admin-password`，不在 `users` 表裡 |
| 登入 | 管理介面自己的 session，存在記憶體，重啟即失效；設定檔憑證改動立即作廢既有登入 |
| 停用 | `admin-password` 留空即無法登入 |
| 嘗試限制 | 規則同 § 97.5「登入嘗試限制」，計數與遊戲登入分開 |
| 數量 | 一組。要多人管理就共用這一組，或各自用主機權限 |

### 頁面

| 頁面 | 內容 |
|---|---|
| 狀態總覽 | tick 耗時（平均／p99／超時次數）、在線人數、連線數、隊伍實例數、SQLite 檔大小、目前 bind 位址 |
| 玩家管理 | 在線玩家列表（帳號、角色、所在地圖、隊伍實例）、踢除連線、封鎖帳號（時限或永久）、**禁言與解除**（§ 97.7.2） |
| 帳號管理 | 帳號列表、發救援碼、註冊開關（開放／邀請碼／關閉） |
| 角色查詢 | 唯讀：等級、位置、背包、統計 |
| 信箱補償 | 發送補償信，沿用 `52-mailbox.md` |
| 備份 | 觸發 SQLite 備份、下載備份檔、graceful shutdown |
| 設定 | 讀寫 `server.properties`（§ 97.2）全部鍵；儲存即寫回檔案，生效時機為「重啟」的鍵儲存後標示需重啟 |

### 不做

- 直接修改角色資料（金幣、物品、等級）
- 修改靜態模板
- 修改資料目錄位置（只能由 `--data-dir` 指定）
- 由管理介面重啟 server

### 操作規則

| 操作 | 規則 |
|---|---|
| 踢除連線 | 先強制 flush 該玩家 dirty state，再斷線 |
| 封鎖帳號 | 立即踢除該帳號所有連線 |
| 發救援碼 | 管理員**不設定、不經手玩家密碼**。產生新救援碼取代舊的，明碼只顯示一次，由管理員交給玩家；玩家在登入畫面以救援碼自行重設（§ 97.5）。不撤銷 session、不踢人，於玩家重設時才撤銷。host 帳號不發。不寄信 |
| 備份 | 於 SQLite WAL checkpoint 後複製，不停服 |
| 設定頁存檔 | 設定值不可含換行；經設定頁修改的 `backup-dir` 必須在資料目錄底下（既有設定不受影響） |
| graceful shutdown | 見下方「關服倒數」 |

#### 關服倒數

管理介面按下 graceful shutdown 後**不立刻斷線**，先給在線玩家 60 秒自己收尾。

| 項目 | 規則 |
|---|---|
| 倒數長度 | 60 秒 |
| 公告時點 | 剩餘 60／30／20／10／5／4／3／2／1 秒各廣播一次 |
| 公告管道 | 全服公告（`notice`），**不走聊天頻道**；client 同時顯示橫幅與寫入系統紀錄 |
| 倒數期間 | 拒絕新連線；遊戲照常進行，玩家可自行登出 |
| 取消 | **不可取消**，重複按只回報已在倒數 |
| 時間到 | 走既有流程：全玩家強制 flush（§ 97.4）→ 關閉 SQLite → 結束 |

## 97.9 已知限制

| 項目 | 限制 |
|---|---|
| NAT / port forwarding | 開服者須自行開通對外連線 |
| 開服者權限 | 可直接修改 SQLite，反作弊對開服者無效；跨服排行不提供 |
| 可用性 | server 關機即停服；單機形態等同關掉程式即停 |
| 備份 | 玩家無匯出手段，SQLite 檔備份由開服者負責 |
| 版本歧異 | 靠 § 97.2 版本協商阻擋 |
| 延遲 | 無 CDN 與多區域部署，取決於開服者網路位置 |
| 既有瀏覽器存檔 | 舊的瀏覽器版（IndexedDB）角色不搬移至 server |
| 城鎮設施位置 | 除旅館外，設施的「須在城鎮」限制只在 client 介面；改過的 client 可在野外使用商店、倉庫、鐵匠鋪、印記師、學技能與新手指導員 |
