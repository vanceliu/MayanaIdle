# 38. 地圖控制系統（Map Control）

## 38.1 系統定位

地圖控制系統將探索與戰鬥場景視覺化為等距（Isometric）俯瞰地圖。玩家以藍點形式在地圖上移動，
怪物以紅點形式依 Pressure 機制持續生成並追蹤玩家，貼近後直接在地圖上展開即時 ARPG 戰鬥，
不切換場景、不進入獨立戰鬥畫面。

本文件負責的範圍：

|---|---|---|

| 紅點生成位置與追蹤行為 | ✅ | |
| Pressure 公式與生成數量 | 引用 | `26-spawn-pressure.md` |
| 戰鬥判定、FSM、技能、投射物、LOS 用途 | 引用 | `41-arpg-combat.md` |
| PixiJS 渲染架構、layer 分工、座標公式 | 引用 | `40-pixijs-migration.md` |

## 38.2 設計原則

- 地圖是探索/戰鬥的**空間層**：地形決定走位、視線與生成位置，不改變傷害公式
- 每個區域/樓層對應一張固定大小的靜態地圖，全部預先設計，執行期不做隨機生成
- 地形必須同時具備**視覺辨識度**與**玩法意義**（阻路、擋視線、限制生成），純裝飾地形只作點綴
- Pressure 機制不變：停留越久，紅點生成越頻繁、同時存在上限越高
- 地圖載入時強制驗證；驗證失敗直接報錯，不得靜默替換為其他地圖

## 38.4 地圖結構

### 格子系統

- 地圖使用 2D 格子（Grid）系統，每格為固定大小的正方形 tile
- 目前使用三種尺寸：**20×15**、**30×20**、**40×30**（含外圍邊界）
- 地圖外圍一圈必須全部是邊界（`1`），由 loader 強制驗證

### 地形 Catalog（單一權威定義）

程式實作見 `client/src/models/mapControl.ts` 的 `TILE_DEFINITIONS`，本表為其設計來源。

| 地形 | 代碼 | 可通行 | 可生成怪物 | 阻擋視線 | 阻擋投射物 | 視覺 role |
|---|---|---|---|---|---|---|
| 地面 | `0` | ✅ | ✅ | ✕ | ✕ | `ground` |
| 邊界 | `1` | ✕ | ✕ | ✅ | ✅ | `boundary` |
| 牆壁 | `3` | ✕ | ✕ | ✅ | ✅ | `wall` |
| 裝飾 | `4` | ✅ | ✕ | ✕ | ✕ | `decoration` |
| 樹木 | `10` | ✕ | ✕ | ✅ | ✅ | `tree` |
| 岩石 | `11` | ✕ | ✕ | ✅ | ✅ | `rock` |
| 柱子 | `12` | ✕ | ✕ | ✅ | ✅ | `pillar` |
| 水池 | `13` | ✕ | ✕ | ✕ | ✕ | `water` |
| 岩漿 | `14` | ✕ | ✕ | ✕ | ✕ | `lava` |
| 深淵 | `15` | ✕ | ✕ | ✕ | ✕ | `chasm` |
| 草叢 | `16` | ✅ | ✕ | ✕ | ✕ | `grass` |
| 沙地 | `17` | ✅ | ✕ | ✕ | ✕ | `sand` |
| 地毯 | `18` | ✅ | ✕ | ✕ | ✕ | `carpet` |

地形分為四類，設計地圖時依用途選擇：

| 類別 | 成員 | 玩法意義 |
|---|---|---|
| **實體障礙** | 邊界、牆壁、樹木、岩石、柱子 | 阻路 + 擋視線 + 擋投射物，可製造掩體與走位空間 |
| **低窪障礙** | 水池、岩漿、深淵 | 阻路但**不擋視線與投射物**，遠程可隔空對射、近戰必須繞路 |
| **裝飾地面** | 裝飾、草叢、沙地、地毯 | 可走但**不生怪**，用於視覺分區與引導動線 |
| **標準地面** | 地面 | 唯一可生成怪物的地形 |

注意：

- 代碼 `2`、`5`~`9` 未使用（保留）
- 玩家進入/重生點由 `spawnPoint` 座標欄位定義，不是 tile 類型
- **所有 tile 高度皆為 0**。單層高台與樓梯尚未實作，見 § 38.15

### 地圖資料格式

```typescript
interface MapData {
  id: string;            // 對應區域/樓層 ID（如 'ivory-tower-1f'）
  name: string;          // 顯示名稱
  width: number;         // 格子寬度
  height: number;        // 格子高度
  theme: MapTheme;       // 環境主題，決定配色（必填）
  tiles: number[][];     // 2D 陣列 [y][x]，每格對應地形代碼
  spawnPoint: Position;  // 玩家首次進入地圖時的起始位置
}

type MapTheme =
  | 'grassland' | 'highland' | 'snow' | 'ivory' | 'forest' | 'swamp' | 'cave'
  | 'prison' | 'battlefield' | 'ancient' | 'dragon'
  | 'tower' | 'frost-tower' | 'lava-tower';

interface Position { x: number; y: number; }
```

- 靜態 JSON 放在 `client/src/data/maps/<id>.json`，以 `import.meta.glob` 動態載入並快取
- 檔名（去除 `.json`）必須等於 JSON 內的 `id`
- 區域對應：無樓層者用 `regionId`，有樓層者用 `${regionId}-${floor}f`；查不到樓層地圖時退回區域地圖

### 載入驗證規則

`validateMapData` 在每張地圖載入時執行，任一項失敗即拋錯（不得靜默替換為其他地圖）：

1. `id` 必須等於請求的 ID，`name` 非空
2. `width` / `height` 為正整數，`tiles` 列數等於 `height`、每列長度等於 `width`
3. `theme` 必須是已定義的主題之一
4. 每個 tile 必須存在於地形 catalog
5. 地圖外圍一圈必須全部是邊界（`1`）
6. `spawnPoint` 在範圍內、可通行、且必須是**可生成格**
7. **所有可通行格都必須能從 `spawnPoint` 走到**（八方向、含防切牆角判定）
8. 至少存在一個可生成格

存檔座標（`mapPositionX` / `mapPositionY`）載入時同樣重新驗證範圍與可通行性，失效則回到 `spawnPoint`。

## 38.5 玩家移動

### 移動方式

| 模式 | 操作 | 行為 |
|---|---|---|
| 手動移動 | 點擊地圖某格 | 角色 A* 尋路走過去，移動中可再次點擊即時改變目的地 |
| 自動移動 | 開啟「自動搜尋」 | 角色優先追蹤最近怪物，無怪時隨機走動 |

### 移動規則

- 移動速度：**2 格/秒**（`moveSpeed`），per-frame 平滑插值
- 尋路：A* 八方向（含斜走），octile heuristic，斜走時兩側正交格皆須可通行（防切牆角）
- 點擊不可通行格：改尋路至最近的可通行格
- 移動中再次點擊：先 snap 到最近整數格，再重新計算路徑
- 關閉自動移動時：立即停止並 snap 到整數格

### 自動移動邏輯

1. 若地圖上有非戰鬥中的怪物 → 選最近一隻，目標設為該怪**相鄰的可通行格**（不是怪物本身的格子）
2. 若無怪物或無路可達 → 隨機選一個目標格
3. A* 計算路徑後開始移動
4. 抵達後等待 **0.5~1.5 秒**再選下一個目標
5. HP/MP 低於門檻進入等待時，自動移動關閉；恢復後若搜尋模式仍為自動則重新開啟

> 注意：隨機目標與怪物生成共用 `getRandomWalkablePosition`，實際只會挑中**可生成格**。
> 因此裝飾地面（草叢/沙地/地毯/裝飾）鋪太多會同時縮小怪物生成池與玩家漫遊範圍，見 § 38.12 的比例限制。

## 38.6 怪物生成（紅點）

### 生成規則

| 項目 | 規則 |
|---|---|
| 判定間隔 | `1000ms ÷ (1 + Pressure × 0.2)` |
| 生成機率 | 每次判定 15% |
| 生成數量 | 每次成功生成 1~3 隻，機率依停留時間，見 `26-spawn-pressure.md` § 26.2 |
| 生成位置 | 隨機**可生成格**，距玩家 ≥ 5 格；最多嘗試 20 次，失敗則放棄本次生成 |
| 同時存在上限 | `min(10, 3 + Pressure)`，見 `26-spawn-pressure.md` |
| 暫停條件 | HP/MP 低於門檻且玩家處於閒置（附近無怪）時停止生成 |

Pressure 公式、上限表與生成數量分布一律以 `26-spawn-pressure.md` 為準，本文件不重複定義。

### 怪物移動

- 速度 **1 格/秒**，per-frame 平滑插值
- 雙模式尋路：
  - 距玩家 **≤ 8 格**：完整 A* 尋路，每 5 秒重算，或玩家移動超過 2 格時立即重算
  - 距玩家 **> 8 格**：greedy one-step（選鄰近最接近玩家的格子），降低計算量
- **佔位互斥**：玩家與每隻怪物各佔一格，下一格被佔用時停在原地等待
- 已在觸發距離內（≤ 1.2 格）的怪物停止移動，原地進入攻擊
- 距玩家超過 **15 格**的怪物直接移除（視為失去追蹤）

> 佔位互斥對地圖設計有直接影響：1 格寬的長走廊會讓後方怪物完全塞住，
> 造成「打完前面一隻才輪到下一隻」的排隊感。走廊寬度規範見 § 38.12。

### Boss 生成

同時滿足下列條件時，該次生成以 **10%** 機率產生 Boss 紅點：

- 該區域怪物池含 Boss（`hasBossInPool`）
- 地圖上尚無 Boss 存在
- 本次進區停留時間 ≥ **10 分鐘**

Boss 紅點以紫色 `#cc00cc` 標示並帶角裝飾。

## 38.7 戰鬥觸發

戰鬥為即時制，與探索共用同一場景，**不切換 phase 畫面**。詳細 FSM、攻擊流程、技能、
投射物與 AOE 判定見 `41-arpg-combat.md`，本節僅記錄與地圖空間相關的部分。

| 項目 | 距離 | 說明 |
|---|---|---|
| 觸發距離 | 1.2 格 | 紅點進入此距離即視為接戰，停止移動並開始攻擊 |
| 近戰攻擊距離 | 1.5 格 | 判定玩家是否處於「戰鬥中」而非閒置的依據 |
| 玩家遠程攻擊 | 依武器/技能 | 需通過 `hasProjectilePath`；水池/岩漿/深淵不擋，牆壁/樹木/岩石/柱子會擋。**遠程技能攻擊同樣適用此判定** |

地形對戰鬥的實際影響：

- **實體障礙**可作為掩體，阻斷投射物與視線
- **低窪障礙**能隔開近戰怪物但擋不住遠程攻擊與遠程技能，形成「安全對射位」
- 怪物持續生成，戰鬥中可能有新紅點加入，形成動態壓力

> **多數怪物為近戰，巫師／魔導系 6 種為遠程魔法**（射程 8 格，見 `25-monster-system.md` § 25.8）：
> 象牙巫師、象牙魔導師、暗影巫師、不死巫妖、霜凍女巫、精靈王魔導士。
> 因此**象牙塔全樓層與百柱塔 21~30F／31~40F／61~70F／91~100F 的低窪障礙已是雙向對射地形**，
> 其餘區域仍維持「玩家單向優勢」。
> **地圖設計不得為了魔法怪重新調整既有地形**（使用者已確認的約束）；
> 上述樓層的實機難度需另行檢視。

## 38.8 與現有系統的整合

### 搜尋模式對應

| 模式 | 地圖行為 |
|---|---|
| 自動搜尋 | 角色自動追怪/漫遊，怪物依 Pressure 生成並靠近 |
| 手動搜尋 | 角色僅依點擊移動，怪物仍依 Pressure 生成並靠近 |

怪物生成完全由 Pressure 與 `mapMonsterStore.spawnTick` 控制，與搜尋模式無關。

### HP/MP 門檻等待

- 每幀檢查 HP/MP 百分比是否低於門檻（預設 HP 30% / MP 20%）
- 低於門檻**且附近無怪**時：停止生成新紅點、關閉自動移動，並輸出等待訊息
- 已存在的紅點仍持續移動，靠近仍會觸發戰鬥（等待會被打斷）
- 回復至恢復門檻以上：自動恢復生成與自動移動
- 常駐腳本（補血/buff）與自然回復不受暫停影響

### 回城 / 死亡

- 使用回城卷軸：離開地圖，傳送至城鎮
- 死亡：離開地圖，傳送至最近城鎮
- 兩者都清除地圖上所有紅點並重置 Pressure

## 38.9 視覺設計

### 視角與座標

- Isometric 45° 等距視角（2.5D），tile 寬高比 2:1（`TILE_W = 64`、`TILE_H = 32`）
- 座標公式與攝影機 lerp 追蹤見 `40-pixijs-migration.md` § 4
- 障礙物以帶高度的立體塊繪製（`WALL_HEIGHT = TILE_H × 0.6`）

### 環境主題配色

配色**不是全域固定值**，而是 14 套 theme palette，實作於 `client/src/pixi/mapThemes.ts`。
每套 palette 提供以下色槽，由 `FloorLayer` / `WallLayer` 依 tile 的視覺 role 取用：

| 色槽 | 用途 |
|---|---|
| `ground` / `groundAlt` | 標準地面，依 `(x + y) % 2` 交錯，形成棋盤紋理 |
| `grid` | 地板格線 |
| `boundaryTop` / `boundaryLeft` / `boundaryRight` | 立體塊的頂面/左面/右面 |
| `obstacle` | 牆壁頂面、岩石、柱子 |
| `decoration` | 裝飾物、樹冠 |
| `water` / `lava` / `chasm` / `grass` / `sand` / `carpet` | 對應地形的地板色 |

實體色（不隨主題變化）：

| 元素 | 顏色 |
|---|---|
| 玩家 | `#4488ff`（藍），帶淡色光暈 |
| 怪物（一般） | `#ff4444`（紅） |
| 怪物（Boss） | `#cc00cc`（紫），帶角裝飾 `#880088` |
| 移動路徑 | `rgba(68,136,255,0.25)` |

### 地形繪製方式

**目前為程式繪製**：地板以主題色盤填菱形，障礙以帶高度的立體塊繪製，
樹／岩石依格座標做確定性擾動（`WallLayer.tileVariance`），避免整片長得一模一樣。

等距地形圖集曾經接上又整批移除，原因與復原需求記錄於下。

#### 障礙物的視覺語彙

同一個灰色系裡塞了四種東西（牆、斷壁、岩石、石柱），只能靠幾何比例分辨，
所以每一種都必須有明確的形狀規則。實作於 `WallLayer`，測試於 `wallLayer.test.ts`。

| 物件 | 形狀 | 判定 |
|---|---|---|
| **牆／邊界** | 整格的等距立方塊，高 `WALL_HEIGHT` | tile 為 `Wall` / `Boundary` |
| **斷壁** | 2~3 塊各自獨立的小方形石材堆在一起 | `Rock` 且**正交**相鄰到牆或邊界 |
| **野外岩石** | 不規則多角形，5~8 角 | 其餘的 `Rock` |
| **直立石柱** | 細高柱身 + 柱頭 | `Pillar` 且非倒柱 |
| **倒塌石柱** | 橫躺的圓柱，跨兩格，兩端有圓形斷面 | `Pillar` 正交成對（見 § 38.12 石柱例外） |
| **雜物（裝飾）** | 箱堆／陶罐／布捆／碎片，四種依格座標輪替 | `Decoration` |

踩過才知道的三條：

- **斷壁不可把整格切開**。沿中軸劈成高低兩半時，那條垂直斷面在等距畫面上
  就是一條把地磚劈開的直線，而且切面貼齊菱形邊緣——讀起來是「畫面被切割」，
  不是「地上有東西」。單塊石材的寬度要明顯小於半格，邊緣才不會與地磚對齊
- **斷壁的高度要明顯低於牆**。兩者高度範圍一旦重疊，斷壁就只是「小一號的牆」
- **倒塌石柱只由成對中座標較小的那格繪製**。兩半各畫一次會完全重疊，
  看起來只是一塊扁平的板子。投影方向也要跟 `worldToScreen` 一致：
  +x 是 (+32,+16)、**+y 是 (−32,+16)**，兩者的 X 符號相反

所有形狀參數都由格座標算出（`tileVariance`），同一格永遠長一樣，重繪不會跳動。

#### 為什麼移除，以及下一套素材的選型需求

原本混用三套來源（Stone Soup 地板、DCSS 物件、LPC 岩石／灌木、Kenney 水岸磚）。
逐項修補只能壓下個別症狀，整體仍然不一致，因此全數移除，
改為尋找**一致性高、最好是同一位作者**的整套等距素材再一次接上。

以下是實際踩過才發現的硬需求，選型時逐條檢查——這些是本輪唯一值得留下的東西：

| 需求 | 為什麼 |
|---|---|
| **物件原生尺寸要一致** | LPC 的樹 43~120px 寬、最高 140px，DCSS 一律 32×32。混在同一張圖上大小差距懸殊，無論怎麼縮放都無法既一致又不超過一格 |
| **物件要能縮到約一格寬** | 統一放大 2 倍會讓大素材漲到兩格寬，樹冠飄在半空、樹幹細得像可以穿過去。縮放只能取整數倍，非整數倍會讓像素風糊掉 |
| **每類物件至少 3 種變體** | 只有一兩種時整片會長得一模一樣。DCSS 只有一顆 `boulder`、只有一種樹樁，都因此不能用 |
| **每張圖都要有可辨識的輪廓** | 有的「樹」其實是 0% 樹葉的樹樁（最寬的一列落在底部），畫出來就是一段木頭立著 |
| **地板要有均勻磚，不能只有方向性磚** | `Dirt_Grass` 這類「草從特定邊緣長進來」的手繪過渡磚，整片鋪開時邊緣會在相鄰格之間對齊，草坪上浮出一格一格的格線 |
| **同一主題的地板變體亮度要接近** | `grass`/`sand` 是同一片地面的材質變體，不是另一個光照層級。亮度差太大會被讀成破洞或聚光燈；且**比地面暗的斑塊讀成坑、比地面亮的才讀成光**，往暗的方向要抓得更緊 |
| **要有各主題真正需要的地形** | Stone Soup 沒有任何白色雪地磚（`Frozen`/`Ice` 都是藍的），雪原因此整張圖是藍的，而 tint 只能變暗、救不回來 |
| **授權要單純** | 合成過渡磚會把兩種地形疊在一起，那是衍生作品。CC0 沒有問題；CC-BY-SA 會讓產生出來的過渡磚也必須以 CC-BY-SA 釋出 |

**目前狀態：素材尚未重新接上**，地圖為程式繪製的色塊。重接時要做的事：

- [ ] 找到一致性高、最好是同一位作者的整套等距素材
- [ ] 一次全部換上，逐條核對上表的選型需求
- [ ] 重接後回頭確認 14 個主題的實機畫面

打包腳本 `client/scripts/packTiles.mjs`（含交界過渡磚合成）已保留，可直接餵新素材；
候選名單與授權研究留在 `client/src/assets/CREDITS.md`。

#### 交界過渡的做法（重新接上素材時沿用）

兩種地板直接相鄰時，菱形邊界會切出一條完全筆直的硬邊。作法是讓鄰居的地形
沿著那條邊**抖動地滲進來**，把直線打散；打包腳本 `client/scripts/packTiles.mjs`
保留了這套合成邏輯（4 bit mask：bit0 NW / bit1 NE / bit2 SE / bit3 SW）。

兩條做對了才有效的規則：

- **一條交界只能由一側畫過渡**。兩側都混合會產生「鄰色→本色→鄰色」的雙重條紋，
  交界反而多出一圈描邊。基底地面讓特色地形滲進來，反之不畫
- **要融向鄰格「實際會被畫出來的」那塊磚**。水池是典型：池邊的水一律畫成淺水，
  若陸地那側仍融向深水，淡出的深藍會直接撞上亮青的淺水，**比不做過渡還明顯**

### Depth Sorting

- 牆壁與實體（玩家、怪物）共用同一個 `EntityLayer`，依 `x + y` 深度排序（`sortableChildren`）
- 實體深度加 `+0.5` 偏移，確保站在同一行牆壁前方時正確顯示
- 移動路徑繪於 `PathLayer`，位於地板之上、實體之下

### 動畫

- 玩家與怪物移動皆為 per-frame 平滑插值
- PixiJS Ticker 驅動（取代舊的手動 `requestAnimationFrame` loop）
- 地板為靜態 Graphics，只在地圖載入時建置一次

### 38.11.1 地形個性：主導地形 + 密度分級

**地圖不得平均分配地形。** 每張地圖必須有明確的個性，讓玩家一眼認得出「這是哪裡」：
有的地圖是密不透風的樹林，有的是幾乎純平原；同一座地牢裡有空曠的大廳層，也有曲折的隔間層。

每張地圖指定三個屬性：

| 屬性 | 說明 |
|---|---|
| **佈局原型** | 骨架結構，見 § 38.12（開闊／半開闊／柱廳／房間走廊／洞窟） |
| **密度分級** | 空曠 / 標準 / 密集 / 極密，決定障礙總量 |
| **主導地形** | 一種特色地形，佔該圖特色地形總量 **≥ 30%** 且必須是最大宗 |

**地形必須混合，不是只有一種。** 明鏡森林要同時有樹、有石頭、有草地、有湖水；
只靠「一種地形鋪滿 + 幾片地板色塊隔開」得不到森林，只會得到色塊拼貼。因此：

- **該主題色盤裡的每一種地形都必須出現，且各佔特色地形總量 ≥ 10%**
- 主導地形只需要「領頭」，不需要壟斷 —— 4 種地形的典型分佈是 **35% / 25% / 22% / 18%**
- 沒有「點綴上限」。壓低其他地形反而是造成單調的原因

主導地形原則：

- 同主題的不同地圖**必須**在主導地形或密度分級上至少有一項不同，不可整組同質。
  換句話說，同主題內「密度 + 主導地形」的組合必須兩兩相異（由 `mapDesignRules.ts` 的測試強制）
- 主導地形決定該圖的**視覺重心**，不是唯一內容：樹木主導 = 以林木為主的森林、
  水池主導 = 湖泊眾多的森林、柱子主導 = 柱林、牆壁主導 = 隔間迷宮、深淵主導 = 斷裂地貌
- 密度分級「空曠」的地圖障礙量本來就少，只需滿足「至少 2 種特色地形」，不受「每種 ≥ 10%」限制
- **主導地形若為裝飾地面類**（草叢 `16`／沙地 `17`／地毯 `18`／裝飾 `4`）：這類地形可走但不生怪，
  其**佔可通行格的比例上限為 35%**，否則會撞到「可生成格 ≥ 60%」的硬性約束（§ 38.12）

## 38.12 佈局原型與設計約束

### 五種佈局原型

| 原型 | 基準可通行率 | 骨架 | 適用 |
|---|---|---|---|
| 開闊型 | 88% | 無內牆，障礙以叢為單位散布 | 野外草原、雪原、戰場 |
| 半開闊型 | 78% | 地形帶（水域/岩帶/裂縫）切割出天然通道 | 森林、沼澤、高地、龍谷 |
| 柱廳型 | 74% | 柱陣 + 局部牆段隔出區塊 | 象牙塔、百柱塔 |
| 房間走廊型 | 65% | 牆壁隔出房間，走廊串連 | 遺跡、水下監獄 |
| 洞窟型 | 63% | 不規則洞室 + 蜿蜒通道 | 朦朧洞窟 |

（可通行率 = 可通行格 ÷ 外圍邊界以內的格數）

### 密度分級

實際可通行率 = **佈局原型基準 + 密度偏移**，容許 ±3% 誤差。

| 密度 | 偏移 | 障礙表現 |
|---|---|---|
| 空曠 | **+8%** | 障礙極少，大片開放空間，視野通透 |
| 標準 | **0%** | 依原型基準 |
| 密集 | **−8%** | 障礙成叢，叢間留明確通道 |
| 極密 | **−16%** | 大片障礙叢，僅留主幹道與數塊空地 |

例：`demon-forest` = 半開闊 78% + 極密 −16% = **62%** 可通行率（密林只留獸徑）；
`dawn-plains` = 開闊 88% + 空曠 +8% = **96%**（近乎純平原）。

**絕對下限 45%**：任何地圖的可通行率不得低於此值。再低會讓 A* 路徑普遍收束到少數窄道，
配合怪物佔位互斥造成嚴重塞車。

### 叢聚分佈原則

這是「密集」與「極密」能成立的關鍵。障礙**必須以叢為單位放置，不得逐格均勻隨機散佈**：

- 均勻散佈 + 高密度 = 滿地 1 格縫隙的假迷宮，怪物到處卡住，視覺上也只是雜訊
- 叢聚 + 高密度 = 密林/亂石堆/柱林 + 林間空地，既讀得出地貌，走位也順暢

規則：

- 每叢障礙**至少 3 格**，叢內可連成塊
- 叢與叢之間保留 **≥ 2 格**的開放通道
- 每張地圖至少保留 **1 塊 ≥ 6×6 的開闊空地**；密集/極密地圖至少 **2 塊**

**沒有叢大小上限。** 一片大森林、一道長岩壁本來就該是大的；限制上限只會讓地圖變成
「同一個尺寸的團塊反覆出現」。防止單一障礙塊吞掉整張圖的責任由可通行率、通道寬度、
繞路上限與開闊空地這四條約束共同承擔，不需要額外的大小上限。
最小值 3 才是關鍵 —— 它擋掉「逐格均勻散佈」那種滿地碎點的假迷宮。

適用範圍與豁免：

- 叢聚規則**只套用在「密集」與「極密」**兩級；「空曠」「標準」的障礙量本來就低，零星單點散落
  反而自然（草原上的孤樹、雪原上的單顆岩石）
- **叢大小限制只套用在自然地貌**（開闊型／半開闊型／洞窟型）。
  **柱廳型與房間走廊型豁免**：柱陣的本質是單格柱子的規則排列，房間牆體本質是長條牆帶，
  兩者強制成叢都會毀掉視覺語彙。人造結構的走位品質改由可通行率與通道寬度約束把關
- **叢間距 ≥ 2 格的規則對所有密集/極密地圖一律適用**，不分自然或人造

### 同一地形的分佈形態

叢聚原則講的是「障礙整體」怎麼放；這一條講的是**單一地形種類**在圖上怎麼散。

**分佈方式由該圖的環境（`theme`）與主導地形決定，沒有一體適用的擺法。**
先問「這個環境該長什麼樣」，再決定這種地形要成片、要散生、還是只出現在特定角落。

| 環境 | 同樣是「水」，該有的樣子 |
|---|---|
| `forest`（如 `mirror-forest`） | 數面各自獨立的靜水鏡池，界線清楚 |
| `swamp` | 水道相連、邊界破碎，與可走的草洲交錯 |
| `cave` | 沿岩壁的積水窪，形狀受地形擠壓 |

樹木同理：`forest` 是成片密林留出林道，`grassland` 是草原上的孤樹與小樹叢，
`snow` 是稀疏枯木。岩石在 `highland` 是連續岩棚，在 `grassland` 只是零星落石。

#### 要避免的是「全部同一種擺法」

環境決定了該地形的個性之後，實際落格時要避免這三種機械排列：

| 反例 | 結果 |
|---|---|
| 全部堆成幾大塊，尺寸相同 | 讀起來是貼皮不是地貌 |
| 全部拆成同尺寸小塊均勻鋪開 | 一眼看得出是程式排的 |
| 全部是單顆 | 缺少地貌重心，畫面碎散 |

也就是說：**同一張圖裡，同一種地形的團塊大小要有差異** ——
幾處成塊當地貌重心，其餘是小群或單顆。至於這些團塊要集中還是散開、
要不要遍佈全圖，由環境決定，不是硬性要求。

另一條實作限制：**單顆障礙必須與其他障礙相鄰**。在「密集」「極密」地圖上，
孤立單格會違反「每叢障礙至少 3 格」；把單顆岩石嵌在林緣或池畔即可 ——
它與樹木/水池同屬障礙，併入同一叢計算，視覺上仍讀作一顆獨立巨石。

#### 石柱是唯一例外

石柱（`12`）是人造結構，語彙是「一根一根立著」，不是自然叢聚：

- **石柱旁邊絕對不會有另一根石柱**，包含斜向
- 最密的排法也必須**至少間隔 1 格**
- 因此石柱不受「每叢障礙至少 3 格」約束（見上方叢聚規則的柱廳型豁免）

由 `checkPillarSpacing` 檢查，屬設計檢查（非安全檢查）。

實例：`demon-forest` 的岩石為東北、東南各一處露頭（成塊）＋ 十餘顆散生單顆；
`mirror-forest` 為東西兩緣各一處露頭 ＋ 池畔散石。

> 分佈正確還不夠。若渲染時同一種地形的每一格長得一模一樣，成片鋪開仍會是重複貼皮，
> 見 § 38.9「地形繪製方式」的逐格外形變化要求。

Boss 層一律使用「空曠」密度，中央保留 **≥ 8×8 開闊空地**。目前的 Boss 層為
`ivory-tower-5f`、`misty-cave-3f`、`underwater-prison-4f`、`dragon-valley-7f`、`ancient-dungeon-9f`
（依 `mapData.ts` 的 `isBossFloor`）。

### 硬性約束

以下每一條都直接對應引擎行為，違反會造成實際玩法問題：

1. **可生成格 ≥ 可通行格的 60%**
   怪物生成只挑可生成格且需距玩家 ≥ 5 格、最多嘗試 20 次；裝飾地面鋪太多會讓生成頻繁失敗，
   自動移動的漫遊目標也會被限縮。
2. **主要通道寬度 ≥ 2 格**
   玩家與怪物佔位互斥，1 格寬的長走廊會讓怪物排隊塞車。1 格寬通道僅可用於短捷徑（長度 ≤ 3 格）。
3. **`spawnPoint` 需要淨空區**：半徑 3 格的**歐幾里得**圓內全部可通行；
   半徑 5 格內可通行格 ≥ 70%。
   進區瞬間玩家需要可活動空間，且怪物最小生成距離 `MIN_SPAWN_DISTANCE = 5` 用的是歐幾里得距離，
   檢查必須採同一種距離才對得上引擎行為。
   實務上把 `spawnPoint` 放在該圖的開闊空地（見叢聚分佈原則）即可自然滿足。
4. **所有可通行格必須從 `spawnPoint` 可達**（loader 強制驗證，含防切牆角）
   低窪障礙（水池/岩漿/深淵）成片鋪設時特別容易切出孤島。
5. **死路（dead end）數量 ≤ 地圖面積 ÷ 50**
   死路本身是合理的關卡設計——壁龕、小房間、裝飾性凹角都會產生死路。
   真正不可接受的是「進不去也出不來」的格子，那由 `validateMapData` 的可達性驗證把關。
   這條只擋「滿地碎口袋」讓自動漫遊一直卡角落的情況，所以門檻放得寬。
6. **地形不得逼出過長的繞路**：任兩個可通行格的實際路徑長度 ≤ `2 × 直線格距 + 10`
   怪物追蹤上限 15 格，被地形逼著繞遠路的紅點會在半路消失，玩家只會看到怪物憑空不見。
   採比例而非絕對值：40×30 地圖的對角直線距離本身就有 37 格，任何絕對上限都會讓大地圖
   幾乎不能放障礙。`+10` 的寬容值則允許繞過單塊岩石之類的短距離繞行。
7. **低窪障礙成片時，至少留一條繞行通道**
   近戰職業無法跨越水池/岩漿/深淵，被隔開會完全打不到對面的遠程怪。

### 手繪時的擺放守則

以下四條不是額外的設計偏好，而是上述硬性約束在「畫地圖」時的具體操作方式。
違反它們產出的違規幾乎都是死路、窄道與過長繞路，而且成因都藏在一兩格的間距裡。

1. **最外一圈要有障礙，但必須貼著邊界成段或以單點出現**。
   整圈淨空會讓玩家可以沿邊繞完整張圖，像跑道一樣；外圈的柱子與扶壁就是用來打斷它的。
   會出事的不是「貼邊的障礙」，而是**離邊界一格的孤立障礙**——它與邊界對夾，
   中間那格就只剩一個出口。所以外圈障礙要嘛貼死邊界、要嘛是單點，不要懸在第二圈。
2. **障礙群之間留 ≥ 2 格可通行**。只隔 1 格時，中間那格的四個正交方向會被兩側封掉，
   斜走又不能切角，於是變成死路。
3. **不可讓三個障礙圍住同一格**。孤立障礙容易無意間與另外兩個排成 ㄇ 字，
   這是死路數量爆掉最常見的來源。
4. **水池離牆 ≥ 2 格**。緊貼牆的水池會在牆與水之間留下 1 格寬的長通道，
   同時觸發窄道與繞路兩條約束。

`npx vite-node scripts/inspectMap.mts <mapId>` 會把違規逐格標回 ASCII 上
（`!` 死路、`n` 窄道、`x` 出生點淨空、`b` 低障礙繞行、`D` 繞路），
比對著改比反覆猜位置快得多。

**改動已建好的地圖時，優先「就地替換」而不是「新增障礙」。**
新增障礙會改變連通性，很容易把原本 2 格寬的通道夾窄、或逼出繞路，
連鎖修補下去整個格局就被打爛了。安全的做法依序是：

1. **就地替換**——把既有的障礙換成另一種障礙（例：牆 → 岩石）。
   兩者同樣不可通行，連通性完全不變，零風險
2. 沒有可替換的對象時，才新增；且**新增的位置必須不影響通道**
   （不可讓任何通道從 2 格變 1 格、不可讓任兩塊區域的繞行距離變長）
3. **裝飾另外個別新增**——裝飾可通行，本來就不擋路；
   只要注意別鋪太多而壓低可生成格比例（下限 60%）

**使用者確認過的地圖是定案，規則不得回頭改它。**
本文件的規則多半是理論上的定義而非實測結論；使用者看過實機、判斷可用之後，
他的判斷優先於規則。對已定案的圖，檢查工具只做**回報**、不做自動修補
（象牙塔 1F 的原版柱牆迷宮就是這樣：它違反 `pillar-spacing`，但那是定案的設計）。

**安全檢查是硬約束，設計指引不是。** `validateMapSafety` 的六項（可生成率、窄道、
出生點淨空、死路、低窪障礙繞行、繞路距離）每張圖都必須全綠；
`reviewMapDesign` 的比例類指標只作事後參考——它們原本是程序生成的目標函數，
硬湊數字只會產出「通過檢查的色塊拼貼」而不是一個「地方」。

實際會打架的兩處，以手繪意圖為準：

- **`cluster-size ≥ 3` 與「樹石要小群或單顆」相衝**。單棵樹、兩顆一組本來就是要的分佈，
  不必為了消掉這條而把所有障礙併成大塊
- **高密度地圖的 `walkable-ratio` 常達不到**。水池是低窪障礙，塘一大就會觸發
  `low-obstacle-bypass`（近戰完全繞不過去）並把中間夾成 1 格寬長廊。
  遇到衝突時放寬可通行率，不要犧牲安全檢查


### 產出方式

**全部地圖逐張手繪**。地形分佈的好壞是視覺判斷，
即使 profile 完全吻合，生成器產出的分佈實際看起來仍是散亂的
（樹排成果園格線、石頭全擠成一大塊），因此**不使用地圖生成器**。

- 每張地圖以 ASCII 稿手繪 tile 陣列，提交為靜態 JSON
- **執行期不做任何隨機地圖生成**（見 § 38.14）
- 全部地圖必須通過 `validateMapData` 與上述硬性約束的自動化檢查
  （`mapDesignCompliance.test.ts`）

#### 作業工具

流程是「畫 → `inspectMap` 逐格定位違規 → 修正 → 重跑」。工具在 `client/scripts/`，可重複使用：

| 工具 | 用途 |
|---|---|
| `inspectMap.mts <mapId>` | 載入驗證 + 安全檢查 + 設計指引，違規逐格標回 ASCII |
| `repairDetours.mts <mapId>...` | 自動打通「兩格之隔要繞十幾格」的牆 |
| `makeFallenPillars.mts <mapId> <n>` | 做出倒塌石柱，每補一格就重驗、退步就撤回 |
| `surveyMaps.mts` | 全庫盤點 |
| `checkSpawnRate.mts` | 各圖最壞情況的生怪失敗率 |

#### 手繪時反覆踩到的坑

**`spawnPoint` 除了可通行，還必須是「可生成格」（只有裸地面）。**
鋪成地毯或裝飾會讓整張圖無法載入，而安全檢查與設計指引都不會抓到這一項。

其餘成因都是低窪障礙擋近戰：

- 水池／熔岩／冰面／深淵連成一大片就繞不過去，要切成多塊、彼此留得出走道
- 流體的端點碰到地圖邊界會把外側走道整段封死，端點要離邊界 ≥3 格
- 30×20 只有 504 格，寬 2 的流很快互相連通把地圖切碎，小圖用寬 1

生怪速率已用 `checkSpawnRate.mts` 驗過：引擎生成時隨機挑可生成格、要求距玩家 ≥5 格、
最多試 20 次。裝飾與地毯可走但**不可生怪**，鋪太多會讓成功率下降。
實測 50 張的最壞情況失敗率都 < 0.0001%，最緊的是 `wind-woods`（附近佔比 36.5%）。

## 38.13 技術架構

### 狀態管理

| Store / 模組 | 職責 |
|---|---|
| `mapControlStore` | 當前地圖、玩家位置、路徑、移動狀態、自動移動開關 |
| `mapMonsterStore` | 紅點列表、生成/移動/碰撞判定、暫停狀態、Boss 池旗標 |
| `gameLoop.ts` | 每幀主迴圈：重建佔位表 → HP/MP 門檻檢查 → 生成 → 怪物移動 → 玩家移動 → DoT tick |
| `occupationManager` | 玩家與怪物的格子佔用表，供尋路避讓 |
| `pathfinding.ts` | A*、最近可通行格、相鄰可通行格、隨機可生成格 |
| `lineOfSight.ts` | 視線與投射物射線判定 |

- 渲染層透過 `getState()` 即時讀取 store，避免 React re-render 打斷動畫
- PixiJS layer 分工與檔案結構見 `40-pixijs-migration.md` § 3、§ 6

### 位置持久化

- 角色資料有 `mapPositionX` / `mapPositionY` 欄位
- `saveGame` 時存入當前位置（snap 到整數格），沿用既有存檔時機（戰鬥結束、切區、回城等）
- 載入時驗證該座標仍在範圍內且可通行，否則回到 `spawnPoint`

### 效能

- 最大地圖 40×30 = 1200 格，A* 在此規模計算極快
- 地板為單一靜態 Graphics，只在載入時建置一次
- 怪物尋路每 5 秒重算（非每幀），距離 > 8 格改用 greedy one-step
- 障礙物與實體共用 `EntityLayer` 的 `sortableChildren` 排序

### 線上化考量

- 目前 client-only，地圖邏輯全在前端
- 未來線上化時，怪物生成與移動需移至 server 端（見 `98-online-architecture.md`）
- 地圖資料為靜態資源，無需動態生成，可直接由 CDN 提供

## 38.14 不做的事

- 不做地圖隨機生成（所有地圖為固定預設計的靜態 JSON）
- 不做小地圖/全域地圖（地圖本身就是全域視角）
- 不做霧戰（Fog of War）
- 不做多人同地圖顯示（未來線上化再考慮）
- 不做地形傷害（岩漿/深淵僅為不可通行，不造成傷害）
- 不因地圖改版新增樓層或改變既有副本結構

## 38.15 未來擴充

以下為方向記錄，尚未實作，不得當作既有規格引用：

- **單層高台與樓梯**：資料結構已預留 `elevation: 0 | 1` 與 `getRenderedElevation`，
  但目前所有 tile 高度皆為 0，且無樓梯地形。實作需同時處理：
  尋路的高低差轉移規則、視線射線的高低差判定、地板側面繪製與 depth sorting
- **遠程物理怪物**：引擎的 `attackType: 'ranged'` 分支已完成，但目前無怪物 seed 使用
  （遠程魔法怪 `attackType: 'magic'` 已上線，見 § 3.1 註記）。
  若未來補上遠程物理怪，需重新檢視水池/岩漿/深淵密度較高的地圖難度（沼澤、龍谷、冰塔）
- **地形移動修正**：草叢減速、沙地減速等
- **可破壞地形**：戰鬥中破壞牆壁改變路徑

- **怪物移動速度依種族/體型差異**：目前固定 1 格/秒
- **玩家移動速度受裝備/buff 影響**：目前固定 2 格/秒
- **安全區**：指定格子永不生成怪物（目前只能用非可生成地形間接達成）
