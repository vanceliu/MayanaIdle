# 38. 地圖控制系統（Map Control）

## 38.1 系統定位

地圖控制系統將探索與戰鬥場景視覺化為等距（Isometric）俯瞰地圖。玩家以藍點形式在地圖上移動，
怪物以紅點形式依 Pressure 機制持續生成並追蹤玩家，貼近後直接在地圖上展開即時 ARPG 戰鬥，
不切換場景、不進入獨立戰鬥畫面。

本文件負責的範圍：

| 範圍 | 本文件 | 其他文件 |
|---|---|---|
| 地圖資料格式、地形定義、地圖設計規範 | ✅ | |
| 玩家移動、尋路、自動移動 | ✅ | |
| 紅點生成位置與追蹤行為 | ✅ | |
| Pressure 公式與生成數量 | 引用 | `26-spawn-pressure.md` |
| 戰鬥判定、FSM、技能、投射物、LOS 用途 | 引用 | `41-arpg-combat.md` |
| PixiJS 渲染架構、layer 分工、座標公式 | 引用 | `40-pixijs-migration.md` |
| 區域/樓層結構與怪物池 | 引用 | `09-dungeon.md` |

## 38.2 設計原則

- 地圖是探索/戰鬥的**空間層**：地形決定走位、視線與生成位置，不改變傷害公式
- 每個區域/樓層對應一張固定大小的靜態地圖，全部預先設計，執行期不做隨機生成
- 地形必須同時具備**視覺辨識度**與**玩法意義**（阻路、擋視線、限制生成），純裝飾地形只作點綴
- Pressure 機制不變：停留越久，紅點生成越頻繁、同時存在上限越高
- 地圖載入時強制驗證；驗證失敗直接報錯，不得靜默替換為其他地圖

## 38.4 地圖結構

### 格子系統

- 地圖使用 2D 格子（Grid）系統，每格為固定大小的正方形 tile
- 目前使用三種尺寸：**20×15**、**30×20**、**40×30**（含外圍邊界）
- 地圖外圍一圈必須全部是邊界（`1`），由 loader 強制驗證

### 地形 Catalog（單一權威定義）

程式實作見 `client/src/models/mapControl.ts` 的 `TILE_DEFINITIONS`，本表為其設計來源。

| 地形 | 代碼 | 可通行 | 可生成怪物 | 阻擋視線 | 阻擋投射物 | 視覺 role |
|---|---|---|---|---|---|---|
| 地面 | `0` | ✅ | ✅ | ✕ | ✕ | `ground` |
| 邊界 | `1` | ✕ | ✕ | ✅ | ✅ | `boundary` |
| 牆壁 | `3` | ✕ | ✕ | ✅ | ✅ | `wall` |
| 裝飾 | `4` | ✅ | ✕ | ✕ | ✕ | `decoration` |
| 樹木 | `10` | ✕ | ✕ | ✅ | ✅ | `tree` |
| 岩石 | `11` | ✕ | ✕ | ✅ | ✅ | `rock` |
| 柱子 | `12` | ✕ | ✕ | ✅ | ✅ | `pillar` |
| 水池 | `13` | ✕ | ✕ | ✕ | ✕ | `water` |
| 岩漿 | `14` | ✕ | ✕ | ✕ | ✕ | `lava` |
| 深淵 | `15` | ✕ | ✕ | ✕ | ✕ | `chasm` |
| 草叢 | `16` | ✅ | ✕ | ✕ | ✕ | `grass` |
| 沙地 | `17` | ✅ | ✕ | ✕ | ✕ | `sand` |
| 地毯 | `18` | ✅ | ✕ | ✕ | ✕ | `carpet` |

地形分為四類，設計地圖時依用途選擇：

| 類別 | 成員 | 玩法意義 |
|---|---|---|
| **實體障礙** | 邊界、牆壁、樹木、岩石、柱子 | 阻路 + 擋視線 + 擋投射物，可製造掩體與走位空間 |
| **低窪障礙** | 水池、岩漿、深淵 | 阻路但**不擋視線與投射物**，遠程可隔空對射、近戰必須繞路 |
| **裝飾地面** | 裝飾、草叢、沙地、地毯 | 可走但**不生怪**，用於視覺分區與引導動線 |
| **標準地面** | 地面 | 唯一可生成怪物的地形 |

注意：

- 代碼 `2`、`5`~`9` 未使用（保留）
- 玩家進入/重生點由 `spawnPoint` 座標欄位定義，不是 tile 類型
- **所有 tile 高度皆為 0**。單層高台與樓梯尚未實作，見 § 38.15

### 地圖資料格式

```typescript
interface MapData {
  id: string;            // 對應區域/樓層 ID（如 'ivory-tower-1f'）
  name: string;          // 顯示名稱
  width: number;         // 格子寬度
  height: number;        // 格子高度
  theme: MapTheme;       // 環境主題，決定配色（必填）
  tiles: number[][];     // 2D 陣列 [y][x]，每格對應地形代碼
  spawnPoint: Position;  // 玩家首次進入地圖時的起始位置
}

type MapTheme =
  | 'grassland' | 'highland' | 'snow' | 'ivory' | 'forest' | 'swamp' | 'cave'
  | 'prison' | 'battlefield' | 'ancient' | 'dragon'
  | 'tower' | 'frost-tower' | 'lava-tower';

interface Position { x: number; y: number; }
```

- 靜態 JSON 放在 `client/src/data/maps/<id>.json`，以 `import.meta.glob` 動態載入並快取
- 檔名（去除 `.json`）必須等於 JSON 內的 `id`
- 區域對應：無樓層者用 `regionId`，有樓層者用 `${regionId}-${floor}f`；查不到樓層地圖時退回區域地圖

### 載入驗證規則

`validateMapData` 在每張地圖載入時執行，任一項失敗即拋錯（不得靜默替換為其他地圖）：

1. `id` 必須等於請求的 ID，`name` 非空
2. `width` / `height` 為正整數，`tiles` 列數等於 `height`、每列長度等於 `width`
3. `theme` 必須是已定義的主題之一
4. 每個 tile 必須存在於地形 catalog
5. 地圖外圍一圈必須全部是邊界（`1`）
6. `spawnPoint` 在範圍內、可通行、且必須是**可生成格**
7. **所有可通行格都必須能從 `spawnPoint` 走到**（八方向、含防切牆角判定）
8. 至少存在一個可生成格

存檔座標（`mapPositionX` / `mapPositionY`）載入時同樣重新驗證範圍與可通行性，失效則回到 `spawnPoint`。

## 38.5 玩家移動

### 移動方式

| 模式 | 操作 | 行為 |
|---|---|---|
| 手動移動 | 點擊地圖某格 | 角色 A* 尋路走過去，移動中可再次點擊即時改變目的地 |
| 自動移動 | 開啟「自動搜尋」 | 角色優先追蹤最近怪物，無怪時隨機走動 |

### 移動規則

- 移動速度：**2 格/秒**（`moveSpeed`），per-frame 平滑插值
- 尋路：A* 八方向（含斜走），octile heuristic，斜走時兩側正交格皆須可通行（防切牆角）
- 點擊不可通行格：改尋路至最近的可通行格
- 移動中再次點擊：先 snap 到最近整數格，再重新計算路徑
- 關閉自動移動時：立即停止並 snap 到整數格

### 自動移動邏輯

1. 若地圖上有非戰鬥中的怪物 → 選最近一隻，目標設為該怪**相鄰的可通行格**（不是怪物本身的格子）
2. 若無怪物或無路可達 → 隨機選一個目標格
3. A* 計算路徑後開始移動
4. 抵達後等待 **0.5~1.5 秒**再選下一個目標
5. HP/MP 低於門檻進入等待時，自動移動關閉；恢復後若搜尋模式仍為自動則重新開啟

> 注意：隨機目標與怪物生成共用 `getRandomWalkablePosition`，實際只會挑中**可生成格**。
> 因此裝飾地面（草叢/沙地/地毯/裝飾）鋪太多會同時縮小怪物生成池與玩家漫遊範圍，見 § 38.12 的比例限制。

## 38.6 怪物生成（紅點）

### 生成規則

| 項目 | 規則 |
|---|---|
| 判定間隔 | `1000ms ÷ (1 + Pressure × 0.2)` |
| 生成機率 | 每次判定 15% |
| 生成數量 | 每次成功生成 1~3 隻，機率依停留時間，見 `26-spawn-pressure.md` § 26.2 |
| 生成位置 | 隨機**可生成格**，距玩家 ≥ 5 格；最多嘗試 20 次，失敗則放棄本次生成 |
| 同時存在上限 | `min(10, 3 + Pressure)`，見 `26-spawn-pressure.md` |
| 暫停條件 | HP/MP 低於門檻且玩家處於閒置（附近無怪）時停止生成 |

Pressure 公式、上限表與生成數量分布一律以 `26-spawn-pressure.md` 為準，本文件不重複定義。

### 怪物移動

- 速度 **1 格/秒**，per-frame 平滑插值
- 雙模式尋路：
  - 距玩家 **≤ 8 格**：完整 A* 尋路，每 5 秒重算，或玩家移動超過 2 格時立即重算
  - 距玩家 **> 8 格**：greedy one-step（選鄰近最接近玩家的格子），降低計算量
- **佔位互斥**：玩家與每隻怪物各佔一格，下一格被佔用時停在原地等待
- 已在觸發距離內（≤ 1.2 格）的怪物停止移動，原地進入攻擊
- 距玩家超過 **15 格**的怪物直接移除（視為失去追蹤）

> 佔位互斥對地圖設計有直接影響：1 格寬的長走廊會讓後方怪物完全塞住，
> 造成「打完前面一隻才輪到下一隻」的排隊感。走廊寬度規範見 § 38.12。

### Boss 生成

同時滿足下列條件時，該次生成以 **10%** 機率產生 Boss 紅點：

- 該區域怪物池含 Boss（`hasBossInPool`）
- 地圖上尚無 Boss 存在
- 本次進區停留時間 ≥ **10 分鐘**

Boss 紅點以紫色 `#cc00cc` 標示並帶角裝飾。

## 38.7 戰鬥觸發

戰鬥為即時制，與探索共用同一場景，**不切換 phase 畫面**。詳細 FSM、攻擊流程、技能、
投射物與 AOE 判定見 `41-arpg-combat.md`，本節僅記錄與地圖空間相關的部分。

| 項目 | 距離 | 說明 |
|---|---|---|
| 觸發距離 | 1.2 格 | 紅點進入此距離即視為接戰，停止移動並開始攻擊 |
| 近戰攻擊距離 | 1.5 格 | 判定玩家是否處於「戰鬥中」而非閒置的依據 |
| 玩家遠程攻擊 | 依武器/技能 | 需通過 `hasProjectilePath`；水池/岩漿/深淵不擋，牆壁/樹木/岩石/柱子會擋。**遠程技能攻擊同樣適用此判定** |

地形對戰鬥的實際影響：

- **實體障礙**可作為掩體，阻斷投射物與視線
- **低窪障礙**能隔開近戰怪物但擋不住遠程攻擊與遠程技能，形成「安全對射位」
- 怪物持續生成，戰鬥中可能有新紅點加入，形成動態壓力

> **目前所有怪物皆為近戰**：怪物 seed 未定義 `attackType`，引擎預設為 `melee`。
> 引擎已具備遠程怪物所需欄位（`attackRange` / `projectileSpeed`）與 FSM 分支，但尚無資料使用。
> 因此低窪障礙目前是**單向優勢**——玩家可隔著水池/岩漿/深淵安全輸出，怪物只能繞路。
> 地圖設計不得預設怪物能隔水攻擊。遠程怪物補上後需重新檢視相關地圖的難度，見 § 38.15。

## 38.8 與現有系統的整合

### 搜尋模式對應

| 模式 | 地圖行為 |
|---|---|
| 自動搜尋 | 角色自動追怪/漫遊，怪物依 Pressure 生成並靠近 |
| 手動搜尋 | 角色僅依點擊移動，怪物仍依 Pressure 生成並靠近 |

怪物生成完全由 Pressure 與 `mapMonsterStore.spawnTick` 控制，與搜尋模式無關。

### HP/MP 門檻等待

- 每幀檢查 HP/MP 百分比是否低於門檻（預設 HP 30% / MP 20%）
- 低於門檻**且附近無怪**時：停止生成新紅點、關閉自動移動，並輸出等待訊息
- 已存在的紅點仍持續移動，靠近仍會觸發戰鬥（等待會被打斷）
- 回復至恢復門檻以上：自動恢復生成與自動移動
- 常駐腳本（補血/buff）與自然回復不受暫停影響

### 回城 / 死亡

- 使用回城卷軸：離開地圖，傳送至城鎮
- 死亡：離開地圖，傳送至最近城鎮
- 兩者都清除地圖上所有紅點並重置 Pressure

## 38.9 視覺設計

### 視角與座標

- Isometric 45° 等距視角（2.5D），tile 寬高比 2:1（`TILE_W = 64`、`TILE_H = 32`）
- 座標公式與攝影機 lerp 追蹤見 `40-pixijs-migration.md` § 4
- 障礙物以帶高度的立體塊繪製（`WALL_HEIGHT = TILE_H × 0.6`）

### 環境主題配色

配色**不是全域固定值**，而是 14 套 theme palette，實作於 `client/src/pixi/mapThemes.ts`。
每套 palette 提供以下色槽，由 `FloorLayer` / `WallLayer` 依 tile 的視覺 role 取用：

| 色槽 | 用途 |
|---|---|
| `ground` / `groundAlt` | 標準地面，依 `(x + y) % 2` 交錯，形成棋盤紋理 |
| `grid` | 地板格線 |
| `boundaryTop` / `boundaryLeft` / `boundaryRight` | 立體塊的頂面/左面/右面 |
| `obstacle` | 牆壁頂面、岩石、柱子 |
| `decoration` | 裝飾物、樹冠 |
| `water` / `lava` / `chasm` / `grass` / `sand` / `carpet` | 對應地形的地板色 |

實體色（不隨主題變化）：

| 元素 | 顏色 |
|---|---|
| 玩家 | `#4488ff`（藍），帶淡色光暈 |
| 怪物（一般） | `#ff4444`（紅） |
| 怪物（Boss） | `#cc00cc`（紫），帶角裝飾 `#880088` |
| 移動路徑 | `rgba(68,136,255,0.25)` |

### 地形繪製方式

| role | 繪製 |
|---|---|
| `ground` / `water` / `lava` / `chasm` / `grass` / `sand` / `carpet` | 平面菱形 tile（`FloorLayer`） |
| `boundary` / `wall` | 立體方塊：頂面 + 左面 + 右面（`WallLayer`） |
| `tree` | 樹幹矩形 + 三顆樹冠圓 |
| `rock` | 不規則多邊形 + 側面暗面 |
| `pillar` | 柱身 + 柱頭菱形 + 明暗面 |
| `decoration` | 兩顆小圓點綴 |

### Depth Sorting

- 牆壁與實體（玩家、怪物）共用同一個 `EntityLayer`，依 `x + y` 深度排序（`sortableChildren`）
- 實體深度加 `+0.5` 偏移，確保站在同一行牆壁前方時正確顯示
- 移動路徑繪於 `PathLayer`，位於地板之上、實體之下

### 動畫

- 玩家與怪物移動皆為 per-frame 平滑插值
- PixiJS Ticker 驅動（取代舊的手動 `requestAnimationFrame` loop）
- 地板為靜態 Graphics，只在地圖載入時建置一次

## 38.11 環境主題地形配方

每個主題定義一組**允許使用的地形色盤**，確保各區域有辨識度。色盤只規定「可以用哪些地形」，
**不規定用多少**——實際比例由每張地圖的個性指派決定（§ 38.11.1、§ 38.11.2）。

| 主題 | 地形色盤 | 環境意象 |
|---|---|---|

### 38.11.1 地形個性：主導地形 + 密度分級

**地圖不得平均分配地形。** 每張地圖必須有明確的個性，讓玩家一眼認得出「這是哪裡」：
有的地圖是密不透風的樹林，有的是幾乎純平原；同一座地牢裡有空曠的大廳層，也有曲折的隔間層。

每張地圖指定三個屬性：

| 屬性 | 說明 |
|---|---|
| **佈局原型** | 骨架結構，見 § 38.12（開闊／半開闊／柱廳／房間走廊／洞窟） |
| **密度分級** | 空曠 / 標準 / 密集 / 極密，決定障礙總量 |
| **主導地形** | 一種特色地形，佔該圖特色地形總量 **≥ 50%**，其餘點綴各 ≤ 20% |

主導地形原則：

- 同主題的不同地圖**必須**在主導地形或密度分級上至少有一項不同，不可整組同質。
  換句話說，同主題內「密度 + 主導地形」的組合必須兩兩相異（由 `mapDesignRules.ts` 的測試強制）
- 主導地形決定該圖的視覺印象：樹木主導 = 森林、水池主導 = 湖沼、柱子主導 = 柱林、
  牆壁主導 = 隔間迷宮、深淵主導 = 斷裂地貌、岩漿主導 = 熔岩地形、地毯主導 = 廳堂
- 密度分級「空曠」的地圖可以只用 1 種特色地形（極少量點綴），視為刻意的平原/大廳表現，
  不受「至少 2 種特色地形」限制
- **主導地形若為裝飾地面類**（草叢 `16`／沙地 `17`／地毯 `18`／裝飾 `4`）：這類地形可走但不生怪，
  其**佔可通行格的比例上限為 35%**，否則會撞到「可生成格 ≥ 60%」的硬性約束（§ 38.12）。
  「主導 ≥ 50%」是相對於**特色地形總量**，不是相對於全圖格數

## 38.12 佈局原型與設計約束

### 五種佈局原型

| 原型 | 基準可通行率 | 骨架 | 適用 |
|---|---|---|---|
| 開闊型 | 88% | 無內牆，障礙以叢為單位散布 | 野外草原、雪原、戰場 |
| 半開闊型 | 78% | 地形帶（水域/岩帶/裂縫）切割出天然通道 | 森林、沼澤、高地、龍谷 |
| 柱廳型 | 74% | 柱陣 + 局部牆段隔出區塊 | 象牙塔、百柱塔 |
| 房間走廊型 | 65% | 牆壁隔出房間，走廊串連 | 遺跡、水下監獄 |
| 洞窟型 | 63% | 不規則洞室 + 蜿蜒通道 | 朦朧洞窟 |

（可通行率 = 可通行格 ÷ 外圍邊界以內的格數）

### 密度分級

實際可通行率 = **佈局原型基準 + 密度偏移**，容許 ±3% 誤差。

| 密度 | 偏移 | 障礙表現 |
|---|---|---|
| 空曠 | **+8%** | 障礙極少，大片開放空間，視野通透 |
| 標準 | **0%** | 依原型基準 |
| 密集 | **−8%** | 障礙成叢，叢間留明確通道 |
| 極密 | **−16%** | 大片障礙叢，僅留主幹道與數塊空地 |

例：`demon-forest` = 半開闊 78% + 極密 −16% = **62%** 可通行率（密林只留獸徑）；
`dawn-plains` = 開闊 88% + 空曠 +8% = **96%**（近乎純平原）。

**絕對下限 45%**：任何地圖的可通行率不得低於此值。再低會讓 A* 路徑普遍收束到少數窄道，
配合怪物佔位互斥造成嚴重塞車。

### 叢聚分佈原則

這是「密集」與「極密」能成立的關鍵。障礙**必須以叢為單位放置，不得逐格均勻隨機散佈**：

- 均勻散佈 + 高密度 = 滿地 1 格縫隙的假迷宮，怪物到處卡住，視覺上也只是雜訊
- 叢聚 + 高密度 = 密林/亂石堆/柱林 + 林間空地，既讀得出地貌，走位也順暢

規則：

- 每叢障礙 **3~24 格**，叢內可連成塊
- 叢與叢之間保留 **≥ 2 格**的開放通道
- 每張地圖至少保留 **1 塊 ≥ 6×6 的開闊空地**；密集/極密地圖至少 **2 塊**

叢大小上限之所以是 24 而非更小：極密自然地貌（`demon-forest`、`dragon-valley-4f`）需要 38% 的
障礙量，扣掉保留的開闊空地後，實際放置區的障礙密度要達 44%。叢間保留 2 格通道時，
n×n 的叢在網格排列下可達密度為 `n²/(n+2)²` —— 12 格上限（3×3）只有 48%，扣掉隨機排列與
邊界的損耗後放不下；24 格上限（4×4）可達 67%，才有足夠餘裕。

適用範圍與豁免：

- 叢聚規則**只套用在「密集」與「極密」**兩級；「空曠」「標準」的障礙量本來就低，零星單點散落
  反而自然（草原上的孤樹、雪原上的單顆岩石）
- **叢大小限制只套用在自然地貌**（開闊型／半開闊型／洞窟型）。
  **柱廳型與房間走廊型豁免**：柱陣的本質是單格柱子的規則排列，房間牆體本質是長條牆帶，
  兩者強制成叢都會毀掉視覺語彙。人造結構的走位品質改由可通行率與通道寬度約束把關
- **叢間距 ≥ 2 格的規則對所有密集/極密地圖一律適用**，不分自然或人造

Boss 層一律使用「空曠」密度，中央保留 **≥ 8×8 開闊空地**。目前的 Boss 層為
`ivory-tower-5f`、`misty-cave-3f`、`underwater-prison-4f`、`dragon-valley-7f`、`ancient-dungeon-9f`
（依 `mapData.ts` 的 `isBossFloor`）。

### 硬性約束

以下每一條都直接對應引擎行為，違反會造成實際玩法問題：

1. **可生成格 ≥ 可通行格的 60%**
   怪物生成只挑可生成格且需距玩家 ≥ 5 格、最多嘗試 20 次；裝飾地面鋪太多會讓生成頻繁失敗，
   自動移動的漫遊目標也會被限縮。
2. **主要通道寬度 ≥ 2 格**
   玩家與怪物佔位互斥，1 格寬的長走廊會讓怪物排隊塞車。1 格寬通道僅可用於短捷徑（長度 ≤ 3 格）。
3. **`spawnPoint` 需要淨空區**：半徑 3 格的**歐幾里得**圓內全部可通行；
   半徑 5 格內可通行格 ≥ 70%。
   進區瞬間玩家需要可活動空間，且怪物最小生成距離 `MIN_SPAWN_DISTANCE = 5` 用的是歐幾里得距離，
   檢查必須採同一種距離才對得上引擎行為。
   實務上把 `spawnPoint` 放在該圖的開闊空地（見叢聚分佈原則）即可自然滿足。
4. **所有可通行格必須從 `spawnPoint` 可達**（loader 強制驗證，含防切牆角）
   低窪障礙（水池/岩漿/深淵）成片鋪設時特別容易切出孤島。
5. **死路（dead end）數量 ≤ 地圖面積 ÷ 100**
   自動移動可能挑到死路盡頭，過多死路會讓漫遊卡在角落。
6. **地形不得逼出過長的繞路**：任兩個可通行格的實際路徑長度 ≤ `2 × 直線格距 + 10`
   怪物追蹤上限 15 格，被地形逼著繞遠路的紅點會在半路消失，玩家只會看到怪物憑空不見。
   採比例而非絕對值：40×30 地圖的對角直線距離本身就有 37 格，任何絕對上限都會讓大地圖
   幾乎不能放障礙。`+10` 的寬容值則允許繞過單塊岩石之類的短距離繞行。
7. **低窪障礙成片時，至少留一條繞行通道**
   近戰職業無法跨越水池/岩漿/深淵，被隔開會完全打不到對面的遠程怪。

### 產出方式

採「重點手工 + 其餘生成」：

- **手工設計**：指標性地圖（象牙塔各層、百柱塔關鍵段、龍谷地間、遠古地監）逐張設計 tile 陣列
- **腳本生成**：其餘地圖以離線 deterministic 腳本依主題配方與佈局原型產出，結果提交為靜態 JSON
- 腳本只在開發期執行，**執行期不做任何隨機地圖生成**（見 § 38.14）
- 全部地圖必須通過 `validateMapData` 與上述硬性約束的自動化檢查

## 38.13 技術架構

### 狀態管理

### 位置持久化

- 角色資料有 `mapPositionX` / `mapPositionY` 欄位
- `saveGame` 時存入當前位置（snap 到整數格），沿用既有存檔時機（戰鬥結束、切區、回城等）
- 載入時驗證該座標仍在範圍內且可通行，否則回到 `spawnPoint`

### 效能

- 最大地圖 40×30 = 1200 格，A* 在此規模計算極快
- 地板為單一靜態 Graphics，只在載入時建置一次
- 怪物尋路每 5 秒重算（非每幀），距離 > 8 格改用 greedy one-step
- 障礙物與實體共用 `EntityLayer` 的 `sortableChildren` 排序

### 線上化考量

- 目前 client-only，地圖邏輯全在前端
- 未來線上化時，怪物生成與移動需移至 server 端（見 `98-online-architecture.md`）
- 地圖資料為靜態資源，無需動態生成，可直接由 CDN 提供

## 38.14 不做的事

- 不做地圖隨機生成（所有地圖為固定預設計的靜態 JSON）
- 不做小地圖/全域地圖（地圖本身就是全域視角）
- 不做霧戰（Fog of War）
- 不做多人同地圖顯示（未來線上化再考慮）
- 不做地形傷害（岩漿/深淵僅為不可通行，不造成傷害）
- 不因地圖改版新增樓層或改變既有副本結構
