# 38. 地圖控制系統（Map Control）

## 38.1 系統定位

地圖控制系統將現有的「隨機遇敵」視覺化為俯瞰視角地圖，玩家以藍點形式在地圖上移動，怪物以紅點形式出現。紅點貼近藍點時觸發戰鬥，進入現有戰鬥流程。

此系統取代原本純文字的「探索中...」狀態，提供直觀的空間感，但不改變核心戰鬥機制。

## 38.2 設計原則

- 地圖是現有探索/戰鬥系統的**視覺化層**，不取代底層邏輯
- Pressure 機制不變：停留越久，紅點（怪物）生成越頻繁
- 戰鬥觸發後進入現有戰鬥流程，地圖暫停
- 每個區域/樓層對應一張固定大小的地圖
- 地圖支援牆壁/不可通行地形，形成簡易迷宮或開闊場地

## 38.4 地圖結構

### 格子系統

- 地圖使用 2D 格子（Grid）系統
- 每格為固定大小的正方形 tile
- 地圖尺寸由各區域定義（如 20×15、30×20 等）

### 地形類型

| 地形 | 代碼 | 說明 | 可通行 |
|---|---|---|---|
| 地板 | `0` | 可行走的路面 | 是 |
| 牆壁 | `1` | 不可通行的障礙 | 否 |
| 入口 | `2` | 玩家重生/進入點 | 是 |

### 地圖資料格式

```typescript
interface MapData {
  id: string;              // 對應區域 ID（如 'ivory-tower-1f'）
  name: string;            // 顯示名稱
  width: number;           // 格子寬度
  height: number;          // 格子高度
  tiles: number[][];       // 2D 陣列，每格對應地形代碼
  spawnPoint: Position;    // 玩家進入地圖時的起始位置
}

interface Position {
  x: number;  // 格子 x 座標
  y: number;  // 格子 y 座標
}
```

### 地圖設計原則

- **迷宮型**：有牆壁路徑限制，需要尋路。適合副本（象牙塔、百柱塔等）
- **開闊型**：少量或無牆壁，自由移動。適合野外區域（曙光草原、翠綠谷地等）
- 每個區域/樓層有自己的地圖，但不需要所有地圖一次做完
- MVP 階段先做 1~2 張測試用地圖

## 38.5 玩家移動

### 移動方式

| 模式 | 操作 | 行為 |
|---|---|---|
| 手動移動 | 點擊地圖某格 | 角色自動尋路走過去，移動中可再次點擊即時改變目的地 |
| 自動移動 | 開啟「自動搜尋」 | 角色隨機走動 |

### 移動規則

- 移動速度：每秒移動 2 格
- 尋路演算法：A* 八方向（含斜走），防切牆角，octile heuristic
- 點擊不可通行格子：尋路至最近的可通行格
- 玩家無法穿越牆壁
- 移動中點擊：立即 snap 到最近整數格，重新計算路徑

### 自動移動邏輯

1. 隨機選擇地圖上一個可到達的格子作為目標
2. 以 A* 計算路徑，開始移動
3. 到達目標後，等待 0.5~1.5 秒，重新選擇下一個目標
4. 若途中觸發戰鬥，中斷移動
5. 戰鬥結束後重新選擇目標繼續

### 手動移動邏輯

1. 玩家點擊地圖格子（Isometric 座標反算）
2. 系統計算 A* 路徑
3. 角色沿路徑平滑移動
4. 到達後停止，等待玩家下一次點擊或切回自動模式
5. 移動過程中再次點擊：立即重新計算路徑至新目標

## 38.6 怪物生成（紅點）

### 生成規則

怪物生成整合現有 Pressure 機制，但改為「地圖上出現紅點」的形式：

| 項目 | 規則 |
|---|---|
| 生成觸發 | 每秒判定一次，基礎生成機率 15% |
| 生成位置 | 地圖上隨機可通行格，距離玩家至少 5 格以上 |
| 同時存在上限 | 基礎 3 隻 + Pressure 加成（見下表） |
| 移動行為 | A* 尋路朝玩家移動（每 3 秒重算路徑），速度 1 格/秒，平滑插值 |

### Pressure 對紅點的影響

沿用現有 Pressure 公式（`26-spawn-pressure.md`），但影響方式改為：

```
地圖同時存在怪物上限 = 3 + Pressure
生成頻率倍率 = 1 + (Pressure × 0.2)
```

| 停留時間 | Pressure | 同時紅點上限 | 生成頻率倍率 |
|---|---|---|---|
| 0~30 分鐘 | 0 | 3 | ×1.0 |
| 30~40 分鐘 | 1 | 4 | ×1.2 |
| 40~50 分鐘 | 2 | 5 | ×1.4 |
| 50~60 分鐘 | 3 | 6 | ×1.6 |
| 60~70 分鐘 | 4 | 7 | ×1.8 |

### 怪物移動

- 紅點以固定速度朝玩家移動（1 格/秒）
- 紅點同樣遵守牆壁限制，使用簡化尋路
- 紅點不會互相碰撞（可重疊）
- 若紅點距離玩家超過一定範圍（如 15 格），紅點消失（視為失去追蹤）

## 38.7 戰鬥觸發

### 觸發條件

當任何紅點與玩家藍點距離 ≤ 1.2 格時，觸發戰鬥。

### 觸發流程

```
紅點貼近玩家（距離 ≤ 1.2）
↓
收集觸發範圍內所有紅點（可能同時多隻）
↓
標記觸發紅點為「戰鬥中」（紅點留在原地不消失、不移動）
↓
停止生成新紅點（其他非戰鬥中紅點仍繼續移動）
↓
進入戰鬥流程（phase = 'combat'），地圖持續顯示
↓
戰鬥結束（怪物全部死亡）
↓
清除戰鬥中的紅點
↓
地圖恢復（phase = 'explore'），恢復生成
```

### 戰鬥中的地圖表現

- 地圖持續顯示，不被遮蔽
- 怪物 HP 列表在地圖上方固定一行水平排列（可水平滾動）
- 戰鬥中的紅點靜止在碰撞位置
- 其他非戰鬥紅點仍然繼續移動（可在戰鬥結束後再次觸發）

### 多隻同時觸發

若同時有多隻紅點在觸發範圍內，全部一起進入戰鬥：
- 戰鬥怪物數 = 觸發範圍內的紅點數量
- 仍受現有最大遇敵數限制
- 超過上限的紅點保留在地圖上，戰鬥後繼續追蹤

### 怪物種類決定

觸發戰鬥時，根據所在區域的怪物池（見 `09-dungeon.md`）隨機決定每隻紅點的實際怪物種類。紅點在地圖上不區分種類，只有觸發戰鬥時才 roll 怪物類型。

## 38.8 與現有系統的整合

### 搜尋模式對應

| 原模式 | 地圖模式對應 |
|---|---|
| 自動搜尋 | 角色自動隨機走動，怪物自動生成並靠近 |
| 手動搜尋 | 角色靜止/手動移動，怪物仍自動生成並靠近 |

注意：原本的 `startExploring` / `rollEncounter` 遇敵系統已禁用，遇敵全由紅點碰撞觸發。

### Pressure 機制

- 計算方式不變（停留時間計算）
- 影響地圖上紅點數量上限與生成頻率
- 重置條件不變（離開地圖/回城/死亡）

### 戰鬥後等待

- **持續每幀檢查** HP/MP 是否低於門檻（預設 HP 30%, MP 20%）
- 低於門檻：角色停止移動、不生成新紅點
- 已存在的紅點仍繼續移動，靠近仍可觸發戰鬥
- HP/MP 恢復到門檻以上：自動恢復移動和紅點生成
- 常駐腳本（補血/buff）和自然回復不受暫停影響

### 回城/死亡

- 使用回城卷軸：離開地圖，傳送至城鎮
- 死亡：離開地圖，傳送至最近城鎮
- 兩者都重置地圖狀態（清除所有紅點、重置 Pressure）

## 38.9 視覺設計

### 視角

- Isometric 45° 等距視角（2.5D）
- Tile 寬高比 2:1（64px × 32px）
- 牆壁有高度（3D 方塊：頂面 + 左面 + 右面）
- Camera follow：玩家永遠在畫面正中央，地圖跟著移動

### 配色

| 元素 | 顏色 | 說明 |
|---|---|---|
| 玩家 | `#4488ff`（藍） | 實心圓，帶淡色光暈 |
| 怪物 | `#ff4444`（紅） | 實心圓，大小略小於玩家 |
| 地板 | `#2a2a3e`（深紫灰） | 菱形 tile |
| 牆壁頂面 | `#222240` | 菱形 |
| 牆壁左面 | `#1a1a2e` | |
| 牆壁右面 | `#0f0f1e` | |
| 移動路徑 | `rgba(68,136,255,0.25)` | 點擊移動時顯示菱形路徑 |
| 格線 | `rgba(255,255,255,0.05)` | 地板格線 |

### Depth Sorting

- 所有實體（玩家、怪物）和牆壁按 `x + y` 深度排序渲染
- 實體 depth 加 +0.5 偏移，確保在同行牆壁前面
- 玩家/怪物會被前方（depth 更大）的牆壁正確遮擋

### 動畫

- 玩家移動：per-frame 平滑插值
- 怪物移動：per-frame 平滑插值（A* 路徑每 3 秒重算）
- 渲染：requestAnimationFrame 驅動，60fps

### 渲染方式

- Canvas 2D 渲染
- useEffect 只依賴 currentMap（不頻繁重啟 animation loop）
- 所有動態值在 render 函數內用 getState() 即時讀取
- 超出可見區域的 tile 做 culling 不渲染

## 38.11 開發階段

### Phase 1：基礎地圖渲染與移動

- Canvas 地圖渲染（地板/牆壁）
- 玩家藍點顯示
- 點擊移動（A* 尋路）
- 自動隨機移動

### Phase 2：怪物系統

- 紅點生成邏輯
- 紅點朝玩家移動
- 碰撞偵測（觸發距離）
- 接入現有戰鬥流程

### Phase 3：Pressure 整合與平衡

- Pressure 影響紅點上限與生成頻率
- 戰鬥後等待行為
- 回城/死亡清除地圖

### Phase 4：完整地圖資料

- 為各區域設計對應地圖
- 地圖切換（進入副本/換樓層）
- 視覺打磨（動畫、特效）

## 38.12 技術考量

### 效能

- Canvas 渲染以 requestAnimationFrame 驅動，目標 60fps
- 地圖格子數量不大（20×15 = 300 格），不需特殊最佳化
- A* 尋路在此規模下計算極快
- 怪物 A* 路徑每 3 秒重算一次（非每幀），避免效能問題
- Tile culling：超出可見區域的 tile 不渲染

### 狀態管理

- 地圖狀態存於 `mapControlStore`（Zustand）：玩家位置、路徑、移動狀態
- 怪物狀態存於 `mapMonsterStore`（Zustand）：怪物列表、生成/暫停狀態
- 戰鬥由 `gameStore.triggerMapCombat()` 觸發，接入現有戰鬥流程
- Render loop 透過 `getState()` 即時讀取所有 store 狀態（避免 React re-render 打斷動畫）

### 位置持久化

- 角色資料新增 `mapPositionX`、`mapPositionY` 欄位
- `saveGame` 時順帶存入當前地圖位置（snap 到整數格）
- 載入角色時以 saved position 恢復地圖位置，而非每次回到 spawnPoint
- 搭乘現有存檔時機（戰鬥結束、切區、回城等），無需額外 interval

### 線上化考量

- 目前為 client-only，地圖邏輯全在前端
- 未來線上化時，怪物生成與移動需移至 server 端
- 地圖資料（tiles）可為靜態資源，無需動態生成

## 38.13 不做的事（MVP 階段）

- 不做即時戰鬥在地圖上（戰鬥仍為獨立 phase）— **未來設計目標，見 §38.15**
- 不做遠程攻擊的視覺表現（未來可擴展）
- 不做多人同地圖顯示（未來線上化再考慮）
- 不做地圖隨機生成（所有地圖為固定預設計）
- 不做小地圖/全域地圖（地圖本身就是全域視角）
- 不做霧戰（Fog of War）

## 38.14 待定項目

- 怪物移動速度是否根據怪物種類/等級有差異
- 是否需要「安全區」（某些格子不會生成怪物）
- 玩家移動速度是否受裝備/buff 影響
- 遠程攻擊是否改變觸發距離（未來擴展）
- Boss 紅點是否有特殊視覺標記

## 38.15 未來設計目標：即時地圖戰鬥

MVP 階段採用方案 A（碰到紅點 → 切換 combat phase → 戰鬥結束回地圖）。

未來目標為方案 B：即時戰鬥直接在地圖上進行，不切換 phase。預期帶來的玩法多樣性：

- **拉怪/風箏（Kiting）**：跑給怪追，拉單隻出來打
- **迴避戰術**：繞牆壁避開不想打的怪群
- **走位策略**：避免被多群怪同時夾擊
- **遠程攻擊差異化**：遠程職業觸發距離大於近戰，可先手攻擊
- **動態增援**：戰鬥中其他紅點可能加入，形成動態壓力

方案 B 需要重構的系統：
- 戰鬥腳本需支援「邊移動邊戰鬥」邏輯
- 怪物攻擊範圍需視覺化
- 多群怪同時戰鬥的 UI 與結算
- 角色攻擊距離與地圖格子的對應

此章節為方向記錄，具體設計待 MVP 驗證體感後再展開。
