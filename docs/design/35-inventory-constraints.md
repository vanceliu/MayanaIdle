# 35. 背包系統限制與規格（Inventory System Constraints）

> 本文件為背包系統的**完整限制清單**，所有實作必須嚴格遵守。  
> AI 實作前必須逐條確認，不可省略或簡化任何規則。

---

## 35.1 容量與格數限制

| 規則 | 說明 |
|------|------|
| 基礎格數 | 背包基礎 **60 格**（`BAG_BASE_SLOTS = 60`） |
| 腰帶擴充 | **腰帶可擴充格數**（`bonusBagSlots`），最高 +20 → 上限 **80 格** |
| 實際格數 | `getBagMaxSlots(equippedGear) = 60 + 腰帶 bonusBagSlots` |
| 擴充來源 | **只有腰帶**。不可新增其他背包擴充管道（道具、金幣購買、等級成長皆禁止） |
| 格子佈局 | 固定 **5 欄**（`BAG_COLUMNS = 5`），無收合功能 |
| 堆疊規則 | 同名消耗品（藥水/卷軸/素材/魔法書）堆疊在同一格，**不佔新格** |
| 裝備佔格 | 每件裝備實例各佔 **1 格**，不可堆疊 |
| **裝備中佔格** | **穿在身上的裝備不會離開背包**，一樣佔 1 格，只是多一個「裝備中」標記 |
| **印記不佔格** | 六種印記收在底部抽屜，**完全不進格數計算**（§ 35.20） |
| 容量計算 | `usedSlots = 非印記的 bagItems + inventory.length + 裝備中件數`（bagItems 每種佔 1 格） |
| 堆疊上限 | 消耗品/素材**無堆疊數量上限** |

基礎 60 格（10 個裝備欄計入佔格）。腰帶階梯 +5 ~ +20，總上限 60+20 = **80 格**。

### 35.1.1 腰帶格數對照表

| 裝備Tier | 腰帶 | 取得 | 擴充格數 | 背包總格數 |
|---|---|---|---|---|
| — | （無腰帶） | — | — | **60** |
| T1 | 皮腰帶 | **新手裝**（跟整套一起發） | +5 | 65 |
| T2 | 鐵扣腰帶 | 商店 | +6 | 66 |
| T3 | 龍皮腰帶 | 商店 | +8 | 68 |
| T4 | 銀扣腰帶 | 鐵匠製作 | +10 | 70 |
| T5 | 力之腰帶（力量+1） | 鐵匠製作 | +15 | 75 |
| T5 | 暗殺者腰帶（敏捷+1） | 鐵匠製作 | +15 | 75 |
| T5 | 賢者腰帶（智力+1） | 鐵匠製作 | +15 | 75 |
| T5 | 祈禱者腰帶（精神+1） | 鐵匠製作 | +15 | 75 |
| T6 | 守護者腰帶（防禦 1） | 怪物掉落 | +18 | 78 |
| T7 | 天龍腰帶（力量+2、防禦 1） | Boss 掉落 | +20 | **80** |
| T7 | 星辰腰帶（智力+2、防禦 1） | Boss 掉落 | +20 | **80** |
| T7 | 幻影腰帶（敏捷+2、防禦 1） | Boss 掉落 | +20 | **80** |

> 腰帶本身穿在身上時**也佔 1 格**（同「裝備中佔格」規則），
> 所以帶著 T1 皮腰帶的實際可用空間是 65 − 1 = 64 格。

腰帶的定位與其他防具不同：**不吃全身防禦目標**，
價值在背包格數與負重。T1~T4 純粹是格數成長，T5 才開始分屬性走向，
T6 不給屬性改給 1 點防禦，T7 是屬性與防禦兼具。

- 腰帶**同時保留原有的負重加成**（`bonusWeight`），兩個效果並存
- 腰帶 `stability: -1`，不可強化（`06-equipment.md` § 6.8）

### 35.1.2 換裝時的溢出保護

裝備中一樣佔格，所以**穿脫本身不會改變佔格數** —— 同一件東西只是從「背包裡」
換成「裝備中」，格子沒動。剩下唯一會溢出的情境是**腰帶讓上限下降**，
判定必須用「換裝後的狀態」，不能只看目前是否已滿。

```
溢出 = 換裝後佔格 > getBagMaxSlots(換裝後的裝備)
```

| 情境 | 佔格變化 | 阻擋條件 |
|---|---|---|
| 卸下一般裝備 | **0** | 不會溢出 → **背包滿了照樣脫得下來** |
| 卸下腰帶 | **0**（但上限少 `bonusBagSlots`） | 換裝後會超出上限 → **禁止卸下** |
| 替換同部位裝備 | **0** | 換成格數較少的腰帶而超出上限 → **禁止換上** |
| 從空手穿上 | **0** | 不會溢出 |

- **禁止卸下**：例如帶著力之腰帶（上限 75）且已佔 61 格，卸下後會變 61/60 → 阻擋，
  戰鬥日誌顯示「背包空間不足，卸下力之腰帶會少 15 格」
- **禁止換上**：力之腰帶（+15）換成皮腰帶（+5）時，若佔格超過 65 → 阻擋
- 玩家必須先清空背包到足夠空間才能卸下／換裝，系統**不自動丟棄任何物品**
- 一般裝備的「背包已滿無法卸除」情境**已不存在**：卸下不再需要新的格子

### 35.1.3 自由放置（Drag & Drop）

背包格子可用拖曳自由擺放，**位置持久化到本機**（§ 35.17）。

| 行為 | 規則 |
|---|---|
| 拖到空格 | 單純移動 |
| 拖到有物品的格子 | 兩者**互換** |
| 拖到自己身上 | 不變動 |

> **觸控裝置不做拖曳**（`47-mobile.md`）：長按已經是次要選單的入口，
> 再讓「按住滑動」抓起格子，玩家想捲背包時每次都會誤觸。
> 觸控的重排改走選單裡的「移動到其他格」→ 點目標格，語意與拖放完全相同
> （目標有東西就互換）。滑鼠玩家兩條路都能用。
| 新獲得物品 | 自動補進**最前面的空格**，不影響已手動擺放的位置 |
| 物品用完／賣掉 | 自動讓出格子，其餘位置不動 |
| 「整理」按鈕 | 把當下的排序結果**整批寫成位置**（§ 35.8） |
| 格數變少（卸下腰帶） | 越界的手動位置**退回自動填格**，物品不會消失 |

**實作模型**：不引入 `slotIndex` 欄位，改用「例外表」——
`slotMap: Record<itemId, slotIndex>` 只記錄被手動移動過的項目，
其餘項目依預設順序填進剩下的空格。
物品增減時不需要任何狀態調和，也不會有 render 期間 setState 的問題。
整理是「一次把所有項目寫進這張表」，不是另一套狀態。

**不做**：物品篩選／搜尋、多頁分頁（本文件 § 35.1.3）。

#### 穿脫不改變格子位置

格子 id 用**裝備實例 id**（`equip-{instanceId}`），穿脫時同一件裝備的 id 不變，
所以有手動位置的裝備不會動。**沒有手動位置的裝備也不可以動** ——
預設順序必須與「是否裝備中」無關，一律依 `EquipmentInstance.id`（取得順序）排，
裝備中與背包裝備**排在同一個序列裡**，不可分成兩段推入。

分兩段推入的話，穿上 A 的同時 B 被換下來，兩件在預設順序中的分組互換，
玩家看到的是「點一下裝備，兩格對調」——位置只該由**整理或拖曳**改變。

> 因此裝備中的裝備**不會自動浮到前面**，要浮上去得按「整理」（§ 35.8）。

### 35.1.4 兩段式點擊

背包格與裝備欄一律**點兩次才動作**：第一次選取該格（金色邊框），第二次才使用／裝備／卸下。

- 選的是**格子**不是「一次動作」：選起來就留著，之後每點一下都直接執行 ——
  連喝三瓶藥水＝點四下，不是選一下用一下地來回切換。
- 點別格會把選取移過去，不會誤觸原本那格。
- **點在有東西的格子以外的任何地方就取消選取**：空格、標題列、金幣列、面板留白，
  裝備欄則是空欄位與欄位標籤。判斷用事件冒泡 + `closest()`，不必逐個子元素攔截。
- **一律走 pointer 事件，不可綁 `click`**（選取、執行、取消選取三者皆是）。`click` 的坑是
  按下與放開落在不同元素時會改派到共同祖先 —— 快速點擊漂幾 px 落到格子間隙就中。
  - **按下（pointerdown）＝選取**：拖曳本身就帶著「按下＝選到這格」的語意，
    所以就算之後真的拖起來，選取一樣已經完成。
  - **放開（pointerup）＝執行**：位移超過 `CLICK_SLOP`（8px）就當拖曳起手，不執行動作。
  - 同一次按壓剛選起來的那格，放開不算「第二次點擊」。
  - 右鍵（快捷鍵選單）不清除選取；**長按剛開完選單的那一下放開也不算執行**
    （`47-mobile.md`）。
- 選取的東西離開背包（用完、穿上、賣掉、丟棄）時選取狀態自動收掉。
- tooltip 提示跟著狀態走：未選取顯示「點擊選取」，選取後顯示「再點一次使用／裝備／卸下」。
- 快捷鍵列與拖曳不受影響，仍是單一動作。

## 35.2 負重系統

背包**同時**受兩個限制：**格子數量**（§ 35.1）與**負重上限**（`20-attributes.md` § 20.7）。
兩者互不取代 —— 格數擋「能帶幾種東西」，負重擋「能帶多重」。

### 35.2.1 目前的狀態

| 項目 | 狀態 |
|---|---|
| 物品重量資料（`weight`） | 生效，背包／倉庫／商店的「重量: N」照常顯示 |
| 腰帶負重加成（`bonusWeight`） | **生效**（T1 +1,700 → T7 +10,000） |
| 負重上限公式（§ 20.7） | **生效** |
| 詳細狀態面板的負重欄位 | **已加回**，超重時轉紅並顯示 ⚠ |
| 超重懲罰 | **已實作**：無法攻擊、無法施放魔法 |

### 35.2.2 超重時的行為

- **無法普通攻擊、無法施放魔法**；移動與自動回血回魔不受影響
- **每次出手判定都會在戰鬥記錄顯示一次**
- 判定受攻擊冷卻限制，訊息頻率等同出手頻率
- 裝備在身上的東西一樣計重

## 35.3 背包已滿處理規則

### 35.3.1 容量檢查時機（所有入口必查）

**印記一律不受這張表約束**（§ 35.20）—— 它不佔格，背包再滿都收得下、買得到、做得出來。

| 入口 | 已滿時行為 |
|------|------------|
| 怪物掉落 | 丟棄掉落物，戰鬥日誌顯示「背包已滿」 |
| 武器商店購買 | 禁止購買，顯示提示 |
| 防具商店購買 | 禁止購買，顯示提示 |
| 雜貨店購買 | 禁止購買，顯示提示 |
| 鐵匠鋪製作 | 禁止製作，顯示提示 |
| 魔法學院製作 | 禁止製作，顯示提示 |
| 倉庫取出 | 禁止取出，顯示提示 |
| 脫下裝備 | **不受背包已滿影響**（裝備中本來就佔著那格）；只有卸下腰帶造成上限下降才擋，見 § 35.1.2 |
| 職業工會任務獎勵 | 禁止交任務，顯示提示 |

### 35.3.2 堆疊例外

- 若背包已有同名消耗品，即使格數已滿 100，仍可累加數量（因不佔新格）
- 範例：背包已滿但有紅色藥水 ×5 → 再獲得紅色藥水 → 數量變 ×6，不占新格

### 35.3.3 顯示格式

- Header 區域顯示：`{usedSlots}/{getBagMaxSlots(equippedGear)}`（如 `48/65`），**含裝備中的件數**
- 當 usedSlots >= 上限的 90% 時，文字顏色改為**警告色**（黃色）
- 當 usedSlots >= 上限時，文字顏色改為**危險色**（紅色）

## 35.4 物品分類與佔格規則

| 分類 | type 值 | 堆疊 | 每種佔格 | 範例 |
|------|---------|------|----------|------|
| 藥水 | `potion` | ✅ | 1 格 | 紅色藥水 ×20 佔 1 格 |
| 卷軸 | `scroll` | ✅ | 1 格 | 回城卷軸 ×5 佔 1 格 |
| 素材 | `material` | ✅ | 1 格 | 銀礦石 ×8 佔 1 格 |
| 魔法書 | `spellbook` | ✅ | 1 格 | 魔法書碎片 ×3 佔 1 格 |

## 35.5 物品互動方式

### 35.5.1 左鍵點擊（主要操作）

| 物品類型 | 點擊效果 |
|----------|----------|
| 藥水 | 使用藥水（`usePotionByType()`） |
| 裝備 | 穿上裝備（`equipItem()`） |
| **裝備（裝備中）** | **卸下裝備（`unequipItem(slot)`）** |
| 回城卷軸 | 使用傳送（`useTownScroll()`） |
| 素材 | 無操作（素材不可直接使用） |
| 魔法書 | 無操作（需至魔法學院使用） |
| 強化卷軸 | 無操作（需至鐵匠鋪使用） |

### 35.5.2 右鍵選單（Context Menu）

| 物品類型 | 選單選項 |
|----------|----------|
| 藥水 | 「設快捷鍵 1~5」、「丟棄」 |
| 裝備 | 「丟棄」 |
| **裝備（裝備中）** | **「設快捷鍵」、「移動到其他格」；不提供「丟棄」** |
| 卷軸 | 「丟棄」 |
| 素材 | 「丟棄」 |
| 魔法書 | 「丟棄」 |

**丟棄規則：**
- **裝備中的裝備一律不可丟棄**（右鍵無此選項、拖到地圖也不觸發丟棄流程），要先卸下來
- 堆疊物品：每次丟棄 **1 個**（amount - 1，歸零時移除該格）
- 裝備：直接移除該實例（從 inventory 移除 + 刪除 DB 記錄）
- 丟棄**不可撤回**，無確認對話框（Idle 遊戲流暢性優先）

### 35.5.3 拖曳（Drag & Drop）

#### 背包內移動

- 有物品的格子可拖，空格不可拖但**可作為放置目標**
- 拖曳中：來源格半透明 + 虛線邊框（`.bag-cell.dragging`）
- 停在目標格：高亮邊框（`.bag-cell.drag-over`）
- 開始拖曳時關閉 tooltip，避免跟著游標殘留
- 詳細規則見 § 35.1.3

#### 拖出背包 = 丟棄

| 放開的位置 | 行為 |
|---|---|
| **地圖上**（`map-canvas-container`） | 視同丟棄，**跳出確認視窗** |
| 其他 UI 介面（面板、城鎮、工具列等） | **不做處理**，物品留在原位 |

> **裝備中例外**：拖曳負載帶 `equipped` 旗標，丟到地圖時直接忽略，不跳確認視窗。
> 重排與快捷格綁定照常可用。

- 判定方式：目標元素以 `data-drop-kind` 宣告自己（地圖是 `map`、快捷格是 `quick-slot`、
  背包格是 `bag-slot`），放開時用 `document.elementFromPoint()` 命中。
  **沒有標這個屬性的區域一律不是落點**，物品留在原位 —— 不需要逐一為其他 UI 加防呆

#### 拖放實作的硬性要求

拖放走 **Pointer Events，不用 HTML5 drag-and-drop** ——
`draggable` + `dragstart/drop` 在觸控裝置上完全不會觸發，
手機玩家等於失去背包重排、快捷格綁定與丟棄（`47-mobile.md`）。

| 要求 | 原因 |
|---|---|
| 拖曳起手必須 `setPointerCapture` | 指標一離開來源格，後續的 move 與 up 就會派給別的元素，拖曳在半路斷掉且永遠收不到落點 |
| 落點必須用 `elementFromPoint`，不可靠事件冒泡 | 指標被來源 capture 住，目標元素根本收不到 `pointerover` |
| 殘影（`.drag-ghost`）必須 `pointer-events: none` | 它只要吃事件就永遠擋在指標正下方，所有落點都會判成殘影自己 |
| 落點語意一律由**拖曳來源**執行 | 快捷格綁定與丟棄都是全域 store action，來源做得完；讓每個目標各自解析拖曳負載會長出三份重複邏輯 |

#### 丟棄確認視窗

| 情境 | 顯示 |
|---|---|
| 堆疊物品（持有 > 1） | 顯示持有數量 + **數量選擇器**（±、直接輸入、「全部」），預設 1 |
| 單一物品或裝備 | 不顯示數量，固定丟 1 |

- 必須有「取消」與「丟棄」兩顆按鈕，點遮罩等同取消
- 數量會夾在 `1 ~ 持有量`，輸入異常值不會產生 0 或負數
- 確認後寫入戰鬥日誌：`丟棄了 {名稱} ×{數量}`（數量 1 時不加後綴）
- **丟棄後無法復原**，視窗須明示
> **與右鍵選單的差異**：右鍵「丟棄」是既有的快捷路徑，固定丟 1 個且不確認；
> 拖到地圖則走本節的數量 + 確認流程。

### 35.5.4 Hover 互動（Tooltip）

所有物品 hover 時顯示 tooltip，延遲 200ms 觸發。

**觸控裝置沒有 hover**（`47-mobile.md`）：改成「選取的同時把詳情叫出來」——
第一次點＝選取＋看詳情，第二次點＝使用，正好是既有的兩段式流程（§ 35.1.4）。
取消選取時詳情一起收掉。

## 35.6 Tooltip 顯示規格

### 35.6.1 消耗品 Tooltip

```
┌─────────────────────────┐
│ {物品名稱}               │  ← 名稱
│ {效果描述}               │  ← 如「回復 HP 50~100」
│ 重量：{weight × amount}  │  ← 總重量
│ 數量：×{amount}          │  ← 堆疊數量
│ 「點擊使用」             │  ← 使用提示（僅可使用物品）
└─────────────────────────┘
```

### 35.6.2 素材 Tooltip

## 35.7 快捷鍵系統

### 35.7.1 快捷欄規格

| 屬性 | 值 |
|------|-----|
| 格數 | **10 格**（`QUICK_SLOT_COUNT`） |
| 觸發鍵 | **`1`~`9` 對應第 1~9 格，`0` 對應第 10 格** |
| 可放物品 | 藥水類、狀態解除道具、回城卷軸、百柱塔通行卷軸、**裝備**、**已習得的技能** |
| 儲存位置 | localStorage（`mayana_prefs_${characterId}.quickSlots`） |

### 35.7.2 可放置的物品與點擊行為

| 類別 | 物品 | 點擊行為 |
|---|---|---|
| 基礎藥水 | 紅／橙／白色藥水 | 使用藥水（`usePotionByType`） |
| 加速藥水 | 綠色／強化綠色藥水 | 使用加速（`useSpeedPotion`） |
| 狀態解除 | 解毒藥水／止血繃帶／淨化藥水 | 解除對應 debuff（`useCureItem`） |
| 回城卷軸 | 三種城鎮回城卷軸 | 傳送回該城鎮（`useTownScroll`） |
| 通行卷軸 | 百柱塔 11F~91F 通行卷軸 | **直飛對應樓層區段**（`changeArea`，會消耗卷軸） |
| 裝備 | 背包中的裝備實例 | **穿／脫切換**：在背包裡就穿上（`equipItem`），穿在身上就卸下（`unequipItem`）。該格**不會自動清空** |
| 技能 | **已習得**的主動技能 | **排入下一個攻擊 tick 施放**（`03-combat.md` § 3.6.2）。不消耗格子內容，可重複使用 |

**放不進去的物品**：強化卷軸、素材、任務物品 —— 判定與點擊行為共用
`resolveQuickSlotAction()`，因此不會出現「放得進去但點了沒反應」。

#### 技能格

技能是快捷欄裡**唯一不來自背包**的內容，因此有三點與物品不同：

| 項目 | 技能 | 物品／裝備 |
|---|---|---|
| 綁定來源 | 技能面板（`SkillPanel`）的已習得技能格 | 背包（`BagPanel`） |
| 用掉會不會消失 | 不會，格子永久保留 | 消耗品用完數量歸零 |
| 不可用時的原因 | CD 中／MP 不足／`requiredWeaponType` 不符 | 數量為 0 |

- 施放時機、目標選取、優先權一律以 `03-combat.md` § 3.6.2 為準，本節不重述
- **未習得的技能不可綁定**；已綁定的技能若因換裝而 `requiredWeaponType` 不符，
  該格灰階但**不清空** —— 換回武器就該恢復可用（`99-ai-constraints.md` § 99.1 第 6 條）
- buff／治癒技能同樣可放。它們的自動化歸常駐天賦（`03-combat.md` § 3.13），
  快捷格是手動補一次，兩者不衝突

#### 通行卷軸直飛

- 目的地由卷軸的**道具 id** 反查 `REGIONS` 中 `entryScrollItemId` 相符的區域，
  **不維護對應表**，改樓層設定時自動跟上。快捷鍵設定本身也存 id 不存名稱
  （`99-ai-constraints.md` § 99.1），道具改名不會讓已綁定的格子失效
- 走既有的 `changeArea()`，因此**會消耗一張卷軸**（與從地圖走過去一致）
- 已經在該區域時不重複進入，只提示「已經在這個區域了」

### 35.7.3 綁定操作

綁定來源有兩個：**背包（物品／裝備）** 與 **技能面板（已習得的技能）**。
兩者走同一套操作、同一份拖放契約，不各做一套。

- **拖放**（主要）：從背包或技能面板把項目拖到快捷欄格子
- **右鍵選單**（既有）：BagPanel 物品／SkillPanel 技能格右鍵 → 「快捷鍵 1~10」
- **長按**（觸控）：與右鍵同一條路徑，長按 500ms 開同一個選單
  —— 手機沒有右鍵，少了它快捷格在手機上綁不上也拆不掉（`47-mobile.md`）
- **未習得的技能格不可拖、不開選單**（`SkillPanel` 會把未習得的格子也畫出來）
- **清除**：QuickSlotBar 上右鍵或長按該格
- 同一個物品拖到新格時，**舊格自動清空**，不會重複佔格

### 35.7.4 排除條件與失效處理

- 焦點在 `<input>` / `<textarea>` 時**不觸發**快捷鍵
- 數量為 0 時該格灰階顯示且不可點
- **不可用 `disabled` 標記不可點的格子** —— 被 `disable` 的按鈕收不到指標事件，
  空格會變成永遠放不進東西。改用 `aria-disabled` + 點擊時自行判斷
- **裝備被賣掉／丟棄／存進倉庫** → 該格失效，點擊時自動清空。
  **穿在身上不算失效** —— 裝備中的裝備還在背包格上，該格改成執行卸下（§ 35.7.2）
- 規則變更後已不可用的物品，載入時由 `normalizeQuickSlots()` 剔除
- **技能格的「不可點」有三種原因，都不清空**：CD 中、MP 不足、`requiredWeaponType` 不符。
  三者都是暫時狀態，清空等於玩家每換一次武器就要重綁一次。
  真正的失效只有一種：**該技能未習得**（讀檔時由 `normalizeQuickSlots()` 剔除）

### 35.7.5 滑鼠兩段確認

滑鼠點擊採**兩段確認**，避免誤點就消耗物品或直接傳送：

| 操作 | 結果 |
|---|---|
| 點擊有內容的格子（未選取） | **只選取**，顯示外框提示，不執行 |
| 再點同一格 | **執行**並解除選取 |
| 點另一格 | 選取移到新格，**不執行**前一格 |
| 點空格／已耗盡的格子 | 不進入選取狀態 |
| 按 `Esc` | 解除選取 |
| 右鍵清除該格 | 一併解除選取 |
| 拖入新物品 | 一併解除選取 |

**鍵盤快捷鍵不受此限** —— 按 `1`~`9` / `0` 一按即發，並清掉滑鼠的選取狀態。
兩段確認是為了防止滑鼠誤點；鍵盤是刻意輸入，再加一段會失去快捷鍵的意義。

選取樣式：`.quick-slot.selected`（外框 + 格號變色）。
Tooltip 會依狀態顯示「點一次選取」或「再點一次使用」。

### 35.7.6 快捷欄顯示

| 類別 | Icon 來源 |
|---|---|
| 基礎藥水 | `getItemIcon('{type}-potion')` + 固定顏色（紅 `#DC2626`／橙 `#F59E0B`／白 `#E2E8F0`） |
| 其他背包物品 | `resolveItemIcon(getItemDefinition(name))` |
| 裝備 | `getEquipIcon()` 依 type／slot，**顏色用 `getEquipmentInstanceTierColor()`（與背包同一套品階配色）** |
| 技能 | `getSkillIcon()` 依元素，顏色用技能面板同一套 `ELEMENT_COLORS` |

- 消耗品顯示剩餘數量 badge；**裝備與技能不顯示數量**

#### CD 指示（技能與藥水）

技能格與藥水格在冷卻中必須同時給出「不能按」與「還要多久」兩個訊息：

| 元素 | 規則 |
|---|---|
| 整格變暗 | 冷卻中降低亮度，與 MP 不足／武器不符的灰階是**同一種**視覺（都是不可點） |
| 扇形遮罩 | 覆蓋**剩餘**冷卻的比例，起點 12 點鐘方向 |
| 指針 | 扇形的邊界線，隨剩餘時間**逆時針**掃回 12 點鐘方向；掃到 0 時遮罩與變暗一起消失，該格恢復可點 |

- 技能的冷卻長度取**實際值**（含 `cooldownReduction`，`03-combat.md` § 3.12），不可用技能表上的原始秒數
- **藥水冷卻是全域共用**（`30-items.md` § 30.1）：三種藥水的冷卻長度不同（600／900／1500），
  但鎖住所有藥水的是**最後喝的那一瓶**。所以三格一起轉，總長取那一瓶的冷卻 ——
  喝白藥就三格都轉 1500ms，喝橙藥就三格都轉 900ms
- 指針更新**不可透過 React state** —— 每格每幀 setState 會讓整條 HUD 每秒重繪數十次。
  直接以 rAF 寫 DOM 的 CSS 變數，且**只在場上至少有一格在冷卻時才啟動**迴圈
- MP 不足與武器不符**只變暗、不畫扇形**：那兩者沒有「還要多久」可言，
  畫了扇形玩家會以為在跑 CD
- 拖曳停留時該格虛線高亮（`.quick-slot.drag-over`）
- 10 格在寬度不足時自動換行（`flex-wrap`）

### 35.7.7 舊格式相容

`normalizeQuickSlots()` 會把舊的 `'red'` 轉成 `{ kind: 'potion', potionType: 'red' }`
並補齊到 10 格；無法辨識的值直接丟棄。
> `assignQuickSlot` / `useQuickSlot`、`QuickSlotBar` 元件。

## 35.8 整理功能

### 35.8.1 排序規則（優先順序）

| 順位 | 內容 | 內部排序 |
|---|---|---|
| 1 | **裝備中**（最多 10 件，含腰帶） | 依裝備欄部位順序（`SLOT_ORDER`） |
| 2 | 藥水 potion | 名稱 |
| 3 | 卷軸 scroll（不含印記） | 名稱 |
| 4 | 素材 material | 名稱 |
| 5 | 魔法書 spellbook | 名稱 |
| 6 | 背包裝備 equipment | 名稱 |

印記歸 `scroll` 但**不在這張表裡** —— 它在自己的分頁（§ 35.20），整理碰不到。

**裝備中是獨立的第一順位，不是裝備類內部的分層** —— 整理完第一排就是身上穿的，
與裝備欄的部位順序對得起來。判斷順序因此是先比「是否裝備中」，再比 type。

空格推到最後方。

### 35.8.2 一次性落位（非 toggle）

「整理」是**單向動作**：按下的當下把排序結果整批寫進 `slotMap`（§ 35.1.3），
每個項目都拿到明確的格子索引。

| 規則 | 說明 |
|---|---|
| 沒有「還原」 | 不保留整理前的快照，要換位置靠拖曳 |
| 不是顯示模式 | 整理完之後**新獲得的物品不再插隊到分類中間**，照 § 35.1.3 補進最前面的空格 |
| 與拖曳同一條路徑 | 整理結果就是 `slotMap` 全表，不引入第二套狀態 |

整理前若已有手動位置，一律被整理結果覆蓋。

## 35.9 裝備穿脫規則

### 35.9.1 裝備（Equip）

| 檢查項目 | 失敗行為 |
|----------|----------|
| 職業限制 | 顯示「{職業}無法裝備此物品」 |
| 等級限制 | 顯示「等級不足」 |
| 雙手武器互斥 | 已裝備副手 → 「需先卸除副手裝備」 |
| 副手互斥 | 已裝備雙手武器 → 「無法裝備 XXX，已裝備雙手武器」 |

**成功流程：**
1. 從背包 `inventory` 移除該裝備實例（**格子不會空出來**，它接著以「裝備中」佔同一格）
2. 若目標欄位已有裝備 → 舊裝備回到背包 `inventory`
3. 新裝備放入目標欄位
4. 觸發持久化存檔

### 35.9.2 卸除（Unequip）

| 檢查項目 | 失敗行為 |
|----------|----------|
| 卸下腰帶造成上限下降而溢出 | 顯示「背包空間不足，卸下{腰帶名}會少 N 格」，**禁止卸除**（§ 35.1.2） |

- **背包已滿不再是阻擋條件**：裝備中本來就佔著一格，卸下只是把那格從「裝備中」改回一般裝備

**成功流程：**
1. 從裝備欄移除
2. 放入背包 inventory（佔格數不變）
3. 觸發持久化存檔

### 35.9.3 入口

裝備欄與背包格**兩邊都能穿脫**，語意一致（兩段式點擊，第二下才動作）：

| 入口 | 第二次點擊 |
|---|---|
| 裝備欄（`EquipmentPanel`）的欄位 | 卸下 |
| 背包格（一般裝備） | 穿上 |
| 背包格（裝備中） | 卸下 |
| 快捷格（裝備） | 穿／脫切換（§ 35.7.2） |

## 35.15 背包格子顯示規格

| 空格處理 | 保留邊框顯示（不隱藏） |

### 35.15.2 格子內容

- **有物品**：圖標 + 名稱 + 數量 badge（右上角）
- **空格**：僅顯示邊框
- **裝備中**：另加**加粗的青色外框**（`--accent-info`）+ 左上角「裝備中」小標。
  小標放左上而非左下 —— 名稱靠格子底部置中，小標壓在左下會蓋掉名稱前幾個字；
  左上只需與右上角的數量 badge 錯開。
  粗框用 inset box-shadow，不可加 `border-width`。
  被選取時金色外框蓋過青色，玩家才分得出自己選到哪一格

### 35.15.3 數量 Badge

- 位置：格子**右上角**
- 顯示條件：amount > 1 時才顯示
- 格式：`×{amount}`

### 35.15.4 Header 資訊

- 頂部顯示金幣數量
- 顯示已用格數 `{used}/{max}`

## 35.17 持久化規則

| 資料 | 儲存位置 | 觸發時機 |
|------|----------|----------|
| bagItems（消耗品） | IndexedDB（characters table） | 物品數量變更時 |
| inventory（裝備） | IndexedDB（equipment_instances） | 裝備穿脫/獲得/丟棄時 |
| quickSlots | localStorage（`mayana_prefs_${characterId}`） | 快捷欄設定變更時 |
| 金幣 | IndexedDB（characters table） | 金幣數量變更時 |
| slotMap（格子位置） | localStorage（`mayana_bag_layout_${characterId}`） | 拖曳／整理後 |

**slotMap 不與角色綁定，不隨角色匯出**：匯入時裝備實例會重新配發 id
（`characterTransfer.ts` 寫入 `id: undefined`），帶過去的 `equip-{id}` 必然全部對不上，
只會留下一堆 stale entry。因此它存在**獨立的 localStorage key**，不進 `mayana_prefs_`。

- 存檔時**剔除不在當前版面的 id**，表不會無限膨脹 ——
  代價是「存進倉庫 → 取出」位置不保留，回到自動填格
- 刪除角色與資料版本清除時必須一併移除該 key（characterId 會被重用）；
  新角色會撿到前一個角色的排列

interface BagItem {

## 35.20 印記抽屜

印記（`46-sigil.md` § 46.2 的六種）**不佔背包格、不計負重**，
收在「一般」分頁底部的抽屜裡（分頁列見 § 35.21）。

**印記維持抽屜，不獨立成分頁**：只有六種、兩排就放得下，抽屜只要一顆 toggle。

### 35.20.1 規則

| 項目 | 規則 |
|---|---|
| 佔格 | **不佔格**。`getBagUsedSlots` 排除印記，`{used}/{max}` 不含印記 |
| 負重 | **不計重**。印記的 `weight` 一律 0（`30-items.md` § 30.2），負重公式不為它開分支 |
| 容量檢查 | 所有入口對印記放行（§ 35.3.1）—— 背包滿了照樣收得到掉落、買得到、做得出來 |
| 收納位置 | 背包面板**底部的「印記」按鈕**，點開由下往上展開抽屜，再點一次收合。預設收合，**開合狀態不持久化** |
| 格數上限 | 印記抽屜**沒有上限概念** —— 種類由 `SIGIL_DEFINITIONS` 決定，堆疊數量無上限 |
| 倉庫 | 照舊可存可取；取出時不做容量檢查 |
| 資料 | 仍存在 `characterBag`，**沒有另開資料表** —— 分頁只是顯示層的切分 |

### 35.20.2 抽屜的開合

| 行為 | 規則 |
|---|---|
| 開 | 點底部的「印記」按鈕，抽屜**由下往上**展開 |
| 關 | 再點一次同一顆按鈕 |
| 位置 | **覆蓋在背包格上方**，不把格子往上推 —— 推擠會讓格子區高度與捲動位置跟著跳 |
| 格數與「整理」 | **永遠顯示** —— 背包格一直都在，抽屜只是蓋在上面 |
| 預設 | 收合，開合狀態不持久化 |

### 35.20.3 印記抽屜不做的事

| 不做 | 原因 |
|---|---|
| 拖曳重排 | 種類固定且只有六種，位置管理沒有意義 |
| 進 `slotMap` | 位置表是格數體系的一部分，不佔格的東西不該混進去 |
| 「整理」 | 同上；整理只作用於背包格 |
| 快捷格 | 印記本來就放不進快捷格（`resolveQuickSlotAction` 不受理），維持原樣 |

保留 tooltip（§ 35.6.1 消耗品格式）與右鍵丟棄（§ 35.5.2）。

### 35.20.4 抽屜不等於多頁背包

§ 35.18 禁的是「把 60 格拆成多頁」來繞過容量上限。印記抽屜**沒有搬走任何一格** ——
背包的格數與上限完全沒變，印記是整個離開格數體系。兩者不是同一件事。

## 35.21 背包分頁列

背包分為兩個分頁：

| 分頁 | 內容 |
|---|---|
| 一般 | 現有背包格 ＋ 底部的印記抽屜（§ 35.20） |
| 天賦 | 自動天賦的鑲材 ＋ **未安裝的天賦格**（`51-auto-talent.md`） |

### 35.21.1 天賦分頁的規則

| 項目 | 規則 |
|---|---|
| 佔格 | **不佔背包格**，不計入 `{used}/{max}` |
| 負重 | **不計負重**，`weight` 一律 0（`30-items.md` § 天賦鑲材） |
| 容量檢查 | 所有入口對鑲材放行（§ 35.3.1） |
| 倉庫 | **不可存入共用倉庫或個人倉庫** |
| 資料 | **不在 `characterBag`**，走獨立實例表（`18-data-schema.md`） |
| 篩選 | 需可依類型（戰鬥／常駐／補給）、種類（條件／實作）、tier、是否已鑲入篩選 |
| 天賦格 | 未安裝的天賦格同樣收在此分頁，規則與鑲材相同（不佔格、不計重、不可存倉庫） |
| 堆疊 | **不可堆疊** —— 每一份是獨立實例，帶各自 roll 出來的參數 |
| 拖曳重排 | **與一般分頁同一套**：拖到別格即換位置，目標有東西就互換，位置持久化 |
| 整理 | **與一般分頁同一套**（§ 35.8）：一次性落位，位置角色別持久化。排序為「天賦格 → 條件 → 實作」，各組高階在前 |
| 位置模型 | 例外表，與 `bagSlotMap` 同一種形狀，共用 `buildBagLayout`／`moveBagSlot` |

天賦分頁是**顯示層在背包、資料層在獨立表**，與印記相反
（§ 35.20.1 的印記資料仍在 `characterBag`，分頁只是顯示層的切分）。

兩個分頁的「整理」是同一顆按鈕、同一個位置、同一種行為：
把當下的排序結果整批寫成位置，之後新拿到的東西排在後面，不插進已排好的分類中間。
差別只在一般分頁的位置是格子索引，天賦分頁是清單順序（那裡不做手動擺放）。

### 35.21.3 三處格子共用同一份設定（硬性）

一般背包格、印記抽屜、天賦分頁**共用同一組欄數與網格樣式**。
各自寫一份的結果是某個分頁比別的窄一圈、格子比別的小一號 —— 玩家一眼看得出來。

| 項目 | 唯一出處 |
|---|---|
| 欄數、補空格、網格容器 | `components/BagGrid.tsx` |
| 拖曳判定（容忍距離、觸控分支） | `hooks/usePressDrag.ts` |
| 天賦分頁的格子與順序 | `models/talentBag.ts` |
| 列高、格子外觀 | `App.css` 的 `.bag-grid` / `.bag-cell` |

天賦分頁的列數對齊一般分頁的格數（`rowsForSlots(maxSlots)`），
兩個分頁切換時視窗高度不會跳。

**拖曳的手感也必須一致**：按下先記著、位移超過容忍距離才轉成拖曳、
觸控不拖（走選單的「移動」），拖曳中來源格 `.dragging` 半透明加虛線。
玩家不會知道自己在哪一個分頁，兩邊手感不同只會像壞掉。

### 35.21.2 分頁列不做的事

| 不做 | 原因 |
|---|---|
| 把印記抽屜改成第三個分頁 | 六種兩排放得下，分頁列與抽屜兩套收納語言不必並存 |
| 依道具分類再切分頁（藥水／卷軸／素材／魔法書） | `BagItemType` 是排序與顯示用的分類，不是分頁；切開會讓格數壓力失去意義 |
